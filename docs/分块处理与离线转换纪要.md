# 分块处理与离线转换纪要（Round 35）

代码：tools/rtaplay.cpp

## 1. 新增能力

    rtaplay in.wav --out out.wav [其余 DSP 选项]     # 离线转换输出
    rtaplay in.wav --chunk 8192 ...                  # 分块处理（默认整块）

两者通常一起用：离线做房间校正 / 升频转换时，用分块处理可**边解码边处理**，
不必把整个文件读进内存。实测 3 秒素材处理耗时 0.302 秒（**9.9x 实时**）。

## 2. 关键验证：真实播放器层面的分块不变性

链路里同时挂着 **EQ（4 个双二阶）+ 卷积 + 升频 2x + 24bit 输出**：

| 对比 | 结果 |
|---|---|
| 整块 vs 8192 帧/块 | **逐位完全相同**（1587600 字节） |
| 整块 vs 1024 帧/块 | **逐位完全相同** |
| 整块 vs **777 帧/块** | **逐位完全相同** |

第三行是关键：**777 既不是 2 的幂，也不是 convBlock(1024) 的整数倍**。
如果管线里任何一个 DSP 对象有分块对齐假设（尤其是均匀分块 FFT 卷积），
这一行必然会暴露出来。

这是对 Round 33/34 流式改造**最强的端到端验证** —— 不是在单元测试里，
而是在真实的播放器程序、真实的完整 DSP 链路上。

## 3. 本轮踩的两个坑

**坑 1：AudioBuffer 的默认格式是 44100/16**
分块拼接时我只在 out.raw.empty() 时设置格式，但那个判断写在 insert **之后**，
于是永远是 false —— 输出头部成了默认的 44100/16（而样本本身是对的 88200/24）。
表面看是 wavcmp 报"格式不同"，真因是元数据没设。

**坑 2：命名空间**
rtaplay 里只 using 了 rta 与 rta::audio，写 PipelineStats 需要 eng:: 前缀。
