# 端点双线程重构纪要（Round 25）

代码：[tools/rtanet_rx.cpp](tools/rtanet_rx.cpp)、[src/net/rtanet.h](src/net/rtanet.h)（新增 `unpop`）

## 1. 重构内容

```
接收线程：recv_from -> 抖动缓冲 + framesIn（绝不做任何等待）
播放线程：按墙钟节奏取数据 -> sink + 每 100ms 回传状态
        时钟未放行时用 JitterBuffer::unpop() 把包放回，绝不丢数据
```

为什么必须解耦（Round 24 定位）：单线程时 deliver 的实时等待会把接收一起阻塞，
framesIn 停在原地，水位指标测出来恒为 0 —— **指标本身是错的**。

## 2. 重构前后对比

| 指标 | 重构前 | **重构后** |
|---|---|---|
| 上报水位 | 恒为 0.0 ms | **211.9 ms**（目标 200，偏差 11.9 ms） |
| 漂移估计 | +291.6 或 -0.0 ppm | **+6.9 ppm**（合理量级） |
| 最终修正 | +159.8 ppm（被 0 水位误导而饱和） | +57.0 ppm（仍在收敛） |
| 逐位完美性 | 保持 | **保持**（2116800 字节逐位相同） |

水位指标从「测错了」变成「可信」，这是本轮的关键突破。

## 3. 可以确认的与仍需验证的

**可以确认**：
- 双线程结构正确：接收不被交付阻塞，水位指标可信（211.9 ms vs 目标 200）
- 漂移估计进入合理量级（+6.9 ppm）
- **闭环不影响逐位完美性**（始终 2116800 字节逐位相同）

**仍需验证**：
- 修正量 +57.0 ppm 尚未收敛到 0（8 秒太短，控制器时间常数约 20-60 秒）
  → 需要跑 60 秒以上的长时间测试
- 真实两机环境（跨真实网卡、真实晶振差异）
