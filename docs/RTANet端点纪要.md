# RTANet 端点程序与真实链路验证纪要（Round 13）

代码：[tools/rtanet_rx.cpp](tools/rtanet_rx.cpp)（端点）、[tools/rtaplay.cpp](tools/rtaplay.cpp)（`--net` 发送）、[tools/wavcmp.cpp](tools/wavcmp.cpp)（逐位比对）

> 遵守 [AGENTS.md](AGENTS.md) 铁律 1：端点**默认 `--sink file`**（写 WAV，不开音频设备）；
> 只有显式 `--sink wasapi` 才出声，且启动前打印警告横幅。

## 1. 两个真实程序跑通的完整链路

```
rtaplay src.wav --net 127.0.0.1:45996        ← DSP 机（含完整 DSP 管线）
        │  TCP 控制面协商 44100/24/2
        │  UDP 690 包 × 808 字节
        ▼
rtanet_rx --sink file --out net_rx.wav       ← 端点机
        │  抖动缓冲按绝对样本号落位
        ▼
net_rx.wav
```

**验证结果**：

```
A: 44100 Hz 2 ch 24 bit 88200 帧
B: 44100 Hz 2 ch 24 bit 88200 帧
字节数: A=529200 B=529200 (长度差 0)
✅ 逐位完全相同 (529200 字节, 176400 样本)
```

**这就是「两机方案」的完整证据**：整条网络链路不引入任何数值改动。

## 2. 端点程序用法

```
rtanet-rx --list                                   # 枚举本机渲染端点
rtanet-rx --sink file --out a.wav --ctrl-port 43210 # 文件 sink（默认，不出声）
rtanet-rx --sink wasapi --device <ID> --buffer 200  # 真正出声（含警告横幅）
rtanet-rx --format 48000/24/2                      # 限定格式（默认接受任意）
```

## 3. ⚠️ 本轮犯的错：把 Round 11 记录过的坑又踩了一遍

**现象**：端点日志显示「收到 8 包，判丢 179960 包，输出 23035904 帧（522 秒）」——
而实际只发了 690 包 / 2 秒。

**原因**：我在接收循环里写成「**缓冲一空就 `fill_gap()` 补静音**」。
静音包瞬间把序号推得飞快，真正的数据包一到就被判成「迟到」丢弃（迟到丢弃 682 包）。

**这正是 Round 11 已经写进文档的那条教训**：
> `pop()` 取不到 ≠ 丢包。补静音必须由调用方依据播放时钟判定超期后才做。

我把 API 设计对了，却在**调用侧**又写错了。

**修复**：
1. 流进行中**绝不**补静音，只交付已连续到达的数据
2. 新增 `JitterBuffer::seal()`：记录已见过的最大序号，封口后 `fill_gap` 不再越过它造静音
3. 流结束（5 秒无包）后统一收尾补缺口

**教训**：把一条规则写进文档**不等于**在每处调用点都遵守了它。
API 设计正确只是必要条件——每个调用点都得重新审一遍。
