# DSD 输出路径打通纪要（Round 47-48）

代码：src/dsp/dop.h（打包）、tools/rtaplay.cpp（--dsd）、tools/dopinfo.cpp（校验）

## 1. 用法

    rtaplay in.wav --dsd 64 --out x.wav --taps 262144 --eq eq.txt
    dopinfo x.wav          # 校验是否为合法 DoP 并统计

## 2. 链路

    输入 -> 升频到 DSD 率(2.8224/5.6448 MHz) -> SDM 调制器(1-bit)
         -> DoP 打包(16 位/样本，标记 0x05/0xFA 交替) -> 24-bit WAV @ 承载率

| DSD | DSD 率 | 承载 PCM 率 | 输出帧数(5 秒源) |
|---|---|---|---|
| DSD64 | 2.8224 MHz | 176400 Hz | 882000 |
| DSD128 | 5.6448 MHz | 352800 Hz | 1764000 |

## 3. 实测（dopinfo 校验）

| 验证项 | DSD64 | DSD128 |
|---|---|---|
| DoP 标记序列合法 | PASS | PASS |
| 1 的比例（直流平衡） | **0.5000** | **0.5000** |
| 结论 | 合法 DoP | 合法 DoP |

### 3.1 端到端信号验证（Round 49）

把 DoP 解回 1-bit 流、再 64 倍抽取成 44100 Hz PCM，测基波：

| | 源 | DSD64 解回 |
|---|---|---|
| 1 kHz 分量 | −60 dBFS | **−59.77 / −59.71 dBFS** |
| 误差 | — | **0.23 dB** |

加上标记合法与直流平衡恰好 0.5000，**这条链路从输入到 1-bit 流是完整的** ——
不只是"格式对"，而是"信号真的在里面"。

1 的比例恰好 0.5000 是调制器工作正常的有力证据 —— DSD 是 1-bit 流，
理想情况下 0 与 1 各占一半。

## 4. 本轮踩的坑

**DoP 承载 WAV 的采样率写成了 DSD 率，应该是 DSD 率除以 16**
（16 个 DSD 位装进 1 个 24-bit 样本）。数据帧数是对的，只有文件头错了 ——
这类错误不会让任何计算失败，只会让接收端按错误的速率播放（音高全错）。
dopinfo 读回来才发现（它打印 2822400 Hz）。

教训：**写文件时"数据对"不等于"文件对"**，必须回读校验。

## 5. 前提与边界

**DAC 必须支持 DoP，且承载率要在它支持的范围内**：

- DoP64 需要 DAC 支持 176.4 kHz
- DoP128 需要 352.8 kHz
- **本机 TASCAM X8 最高 96 kHz，无法承载 DoP** —— 实际试听需要你的接收 DAC

**目前只支持离线输出（--out）**，尚未接到实时播放（WASAPI 独占）
——因为本机没有能承载 DoP 的设备，接了也无法验证。
