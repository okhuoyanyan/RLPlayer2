# Hi-Fi 回放领域 —— 下一批脑洞（2026-10-27）

> 目标：跳出「对标 HQPlayer 补功能」的框架，看 RLPlayer 还能在**哪些别人没做好的地方**做出差异。
> 每条给：**一句话想法 / 为什么现在没人做好 / 我们的天然优势 / 工作量 / 可验证判据 / 风险**。
> ⚠️ 全部是设想，**未立项、未改动任何代码**。

---

## 0. 判断基准：我们的天然优势是什么

在挑方向之前先认清手里的牌，不对着优势挑就是白挑：

1. **是唯一的「透明」音频中介**：文件从解码到 DAC 全程可控，任何一级都能插测量点。
   ⟹ 我们**知道自己在播什么、每一级发生了什么**，Roon / HQPlayer / JRiver 对用户都是黑盒。
2. **有 GPU DSP（含 AMD ROCm，本机 gfx1201）**：实时卷积、多声道矩阵都已经跑起来。
   ⟹ 适合做**按曲目/按房间/按耳机动态生成 DSP** 的事，别人只能预生成。
3. **有全信源元数据层**（5 个数据源 + AI 摘要 + 曲库解析）。
   ⟹ 能做「内容理解」，而不只是「文件播放」。
4. **有自研 RTANet**：网络投放端到端自己掌控。⟹ 能做时钟闭环、抖动诊断这类别人碰不到的事。
5. **是面向发烧友的产品，用户愿意为「可解释」付钱**。
   ⟹ **可解释性本身就是产品**，而不是附属的 debug 功能。

---

## 1. 【强烈推荐】播放链路「行车记录仪」

**想法**：把每一次播放的整条链路（解码 → 升频 → 卷积 → 抖动 → 输出缓冲 → 设备时钟）
记录成一份可回放的**证据包**：每个阶段的事件、欠载/丢样、设备实际吞吐、时钟漂移、DSP 实际参数。

**为什么没人做好**：所有竞品播坏了只会说「你设备的问题」。
用户说「有破音」时，厂商、声卡厂、用户三方互踢皮球——**这正是本项目 debug/20261022-02 和 20261024-01 里真实发生过的事**。
（N300「边播边啵啵啵」，最后定位是**输出吞吐只有 0.39 倍实时**，不是削波。）

**我们的优势**：这条链路是我们自己写的，每个判断点天然存在（STAT / PLAYBUF / WFAIL / DEVICE_LOST 已经在产生了）。

**工作量**：中（1~2 周）。主要是把现有日志规范化 + 一份「一键导出证据包」+ 一个本地分析视图。

**可验证判据**：人为制造 3 类故障（CPU 抢占、设备拔掉、源文件读失败），每类都要在证据包里**直接指认到具体阶段**，
而不是让用户去猜。**能指着日志说「第 37 秒第 3 级缓冲欠载，原因是被 XX 抢占」才算成。**

**风险**：低。这是纯增量，不碰音频路径。

---

## 2. 实时测量 + 「我听到的 vs 它给我的」

**想法**：用输入采集做一次 **loopback 实测**——播放一段测试信号或用户自己的曲目，
把设备**实际输出回来的信号**与**我们送出的信号**做差，得到真实的 THD+N、频响、声道平衡、串扰、延迟。

**为什么有意义**：发烧友常年争论「DAC 的 XX 模式是不是真的 bit-perfect」「EQ 是不是把相位搞坏了」。
现在这些只能靠第三方测量仪（Audio Precision，几万块）或信仰。
**我们能直接给数字，而且能给「此刻、我这台机器、这个驱动版本」的数字。**

**我们的优势**：整条链路可控 ⟹ 送出的参考信号是**精确已知**的（这正是一般播放器做不到的）。

**依赖**：已有的输入采集链路（麦克风 / 回环），A5「输入采集监听不过 DSP 链」要先补。

**工作量**：中高（2~3 周）。需要：精确参考信号生成、对齐（延迟无关的频域判据——**别用时域逐点比对，会被延迟估计误差完全支配**，见铁律 3）、多声道路由。

**可验证判据**：已知缺陷的 DAC/环路必须测得出对应的 THD+N 恶化；已知正常的链路误差要低于本底噪声。**用「能测出已知问题」来证明测量本身是对的。**

**风险**：中。**必须遵守铁律 1**——测试信号一律 ≤ −60 dBFS，且要用户显式同意才可闻。

---

## 3. 按曲目自动生成 DSP（内容自适应的 EQ / 空间）

**想法**：把音乐内容分析（见 `docs/音乐内容分析-设想.md`）接到 DSP 上：
识别出这是「人声为主的爵士」还是「低频很挤的电子」，自动选不同的**前级增益、低频管理、空间处理**。

**为什么把这条放在第 3 而不是第 1**：它看起来最诱人，但**违反了 Hi-Fi 的第一原则——不擅自改变用户听到的东西**。
所以正确的形态不是「自动 EQ」，而是「**建议 + 一键应用**」，且必须能解释为什么建议。

**我们的优势**：分析层和 DSP 层都在我们手里，别人的链路是断的。

**工作量**：中（依赖内容分析先做出来）。

**可验证判据**：同一首歌重复分析结果一致；建议必须附**依据**（例如「这首歌频谱质心 2.8 kHz，低频能量占比 34%，比你的既往偏好高」）；
用户一键关闭后，任何 DSP 参数都不得残留。

**风险**：中高（容易做成「自动音染」而失去发烧友信任）。**默认必须关闭。**

---

## 4. 实时「音质体检」而不是靠耳朵找问题

**想法**：播放时实时累计统计：欠载次数、缓冲积压趋势、设备时钟漂移率、DSP 是否真的在目标采样率上跑、
是否发生了隐式重采样、是否出现削波。用一个「健康度」指标显示，出问题时告诉用户**哪一环**。

**为什么没人做**：因为竞争对手的架构里没有这一层的可见性（黑盒直出）。

**我们的优势**：这其实就是 §1 的「在线版」。**两者应该一起做，共用一个事件模型。**

**工作量**：低（数据已经在产生，只是没有汇总和呈现）。

**可验证判据**：故意把系统时钟拉偏 / 制造一次软欠载，健康度必须变化且归因正确；正常播放 1 小时必须零误报。

**风险**：低，但**误报会毁掉信任**——宁可少报。

---

## 5. 「房间/耳机测量 + 自动纠正」的完整闭环

**想法**：用麦克风（UMIK 之类）扫频测房间，自动生成 PEQ + 多声道分频 + 相位对齐；
或者接 OPRA（`docs/耳机EQ-OPRA调研与设计.md` 已有方案）一键应用耳机曲线。

**现状**：OPRA 方案已经调研完（714 厂商 / 6230 产品 / 12594 条预设，CC BY-SA 4.0 合规），**只是没实施**。
房间测量部分还没有。

**工作量**：OPRA 接入是低（就是 biquad 数据，和 `matrix.h` 同源）；房间测量是中高（需要扫频 + 窗函数 + 逆滤波 + 多声道）。

**可验证判据**：测量回路必须能在已知缺陷（故意插 6 dB 峰）上测回收敛后的削平；OPRA 预设应用后的频响与预设定义逐点吻合。

**风险**：低（OPRA）/ 中（房间测量，测量误差会直接变成错误的 EQ）。

---

## 6. 输出设备「能力指纹」

**想法**：每次接上一台 DAC，自动测并记录它的**真实能力**：支持的采样率/格式、DSD 族、
实际能开的最大缓冲、实测吞吐率、有没有隐式 SRC、驱动版本的已知 bug 清单。

**为什么有用**：本项目已经被设备能力坑过多次（48k DSD 族、N300 的 0.39× 吞吐、ASIO 原生 DSD 的类型 33）。
把这些做成**持久化、跨用户共享（可选匿名上传）的知识库**，新用户第一次就能避开坑。

**工作量**：低（探测逻辑大部分已有，只是没沉淀）。

**可验证判据**：对已知的几台设备（本机 X8、用户的 N300）探测结果与人工确认一致。

**风险**：低。

---

## 7. 网络投放的时钟质量可观测

**想法**：RTANet 已经有闭环回传。把**时钟漂移率、重同步次数、丢包**做成可见指标，
并且给用户一个「这条链路还能不能算 bit-perfect」的明确判断。

**为什么别人做不到**：HQPlayer 的 NAA 是黑盒私有协议；我们用自研协议，能在两端都插探针。

**工作量**：中（闭环已有，主要是呈现与判据定义）。

**可验证判据**：人为注入时钟偏差与丢包，必须能定性识别并归因。

**风险**：低。

## 8. 明确**不建议**碰的方向（写下来免得反复讨论）

| 想法 | 为什么不建议 |
|---|---|
| **实时 AI 分轨做「伴奏消除」** | 算力不可行（本机 AMD 无 torch GPU），且本质是**改变内容**，不是 Hi-Fi |
| **自动 EQ 永远开着** | 违反「不擅自改变用户听到的」原则，老烧不会要 |
| **抓 QQ 音乐 / 网易云原始流** | 技术上不可行、法律上违法（见 `docs/音乐平台截流可行性.md`）；loopback 只能当降级输入 |
| **在线调音社区/分享 EQ** | 运营成本高、内容质量难控，容易变成灌水 |
| **追求更深的阻带衰减** | **已经在 `docs/音质极限分析.md` 里总结过：−120 dB 以下对听感没有意义，我优化错了指标**。不要重复踩 |

---

## 9. 如果只挑一条先做

**§1 + §4（行车记录仪 + 健康度）**，因为：

- 它直接对应**用户已经抱怨过的真实问题**（破音、啵啵啵），不是想象出来的需求；
- **数据已经在产生**，主要工作是整理与呈现，代价最小；
- 它是「可解释性」这个差异点的地基——后面 §2、§6 都要复用它的事件模型；
- **做坏了也伤不到音质**（纯旁路）。

其次是 **§5 的 OPRA 部分**：调研已经做完，实施代价最低，用户感知最直接。
