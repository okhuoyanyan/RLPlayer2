# 播放器第二轮纪要（界面 / 流式渲染 / 音质补充）

日期：2026-10-20
范围：把"能跑的命令行工具"做成"能日常听的播放器"这一轮里踩到的坑与新能力。

---

## 0. 这一轮到底改了什么

| 方向 | 之前 | 现在 |
|---|---|---|
| 播放方式 | 整曲解码 -> 整曲 DSP -> 整块写设备 | **流式**：生产者分块解码+DSP，消费者按【整周期】写设备 |
| 内存占用 | 705.6 kHz / 5 分钟需要 **1.7 GB**，还会被 VirtualLock 锁死 | 恒定几秒（队列上限 8 块） |
| 起播延迟 | 要等整曲处理完 | 等第一块（约 100 ms 音频）处理完 |
| 库管理 | 只有目录树，默认打开磁盘根目录（空的） | 专辑网格 + 艺术家 + 全局搜索 + 封面 |
| 歌词 | 无 | 同名 .lrc / 同目录 .lrc / 内嵌标签，GBK 自动转码，逐行同步高亮 |
| 播放列表 | 无 | 新建 / 保存 / 载入 / 删除（playlists 目录下的 m3u8，标准格式） |
| 信号链 | 无 | Roon 式弹层：源文件 -> 解码 -> 重采样 -> 抖动 -> 音量 -> 设备 |
| 音量 | 只能起播前设定 | 播放中实时拖动（0 dB 时逐位旁路） |
| 抖动 | 手动选 | 新增 auto：按输出位深选 NS9 / LNS15 / 无 |
| 削波保护 | 无 | **过采样峰值检测**，超出满幅时自动预衰减（可关） |

## 1. 六个真凶（都值得记住）

### 1.1 /api/pl 前缀把 /api/play 吃掉了

    if (rq.path.rfind("/api/pl", 0) == 0) { ... }   // /api/play 也匹配！

**现象**：点播放返回的是播放列表的 JSON，播放根本没开始，队列为空。
**教训**：所有前缀匹配的 API 路由，要么带结尾斜杠（/api/pl/），要么额外判等。
**同类风险**：/api/lib 与将来的 /api/library、/api/src 与 /api/srcx。

### 1.2 独占 + 事件回调模式下，GetBuffer 必须正好一个周期

    GetBuffer(8917)  ->  AUDCLNT_E_BUFFER_SIZE_ERROR (0x88890016)，一个字节都不写
    GetBuffer(9600)  ->  OK（9600 = 一个周期 = 缓冲长度）

**现象**：界面显示"播放中"，但进度永远停在 0 秒。
**根因**：DSP 分块长度（8917 帧）不是周期（9600 帧）的整数倍。
**修法**：消费者维护一个"待写缓冲"，攒够一个周期再整周期写入（末尾补静音凑满）。
**注意**：旧版之所以没踩到，是因为它整曲处理完，每次正好有整周期的数据 —— 典型的"换个写法就暴露"。

### 1.3 IAudioClient::Reset() 之后 padding 不恢复

**现象**：拖动进度条后，进度卡死不动。
**根因**：Reset() 会停流；重开后 GetCurrentPadding() 仍报满，GetBuffer 永远拿不到空间。
**修法**：跳转时**不调用 Reset**，只清空本地待写缓冲 + 用 epoch 丢弃旧数据；
代价是设备缓冲里最多 1 个周期（约 100 ms）的旧音频会先播完。

### 1.4 丢弃旧块后没有唤醒生产者 —— 真凶中的真凶

    while (!RQ.q.empty()) {
        if (f.second != myEpoch) { RQ.q.pop_front(); continue; }   // 丢旧块
        ...
    }
    if (RQ.done) ...
    return false;        // ← 这里没有 notify，生产者永远卡在 "队列满" 的 cv.wait 上

**现象**：跳转后旧数据被丢光了，但生产者还在睡，队列一直是空。
**修法**：任何一次 pop_front() 之后都要 notify_all()；返回 false 前也补一次。

### 1.5 事件流一旦断供就再也不来

**现象**：短暂没有数据（跳转重算的那 200 ms）之后，WaitForSingleObject 永久超时。
**根因**：独占事件驱动流要求"每个事件都被响应（写入）"，错过之后驱动停止发事件。
**修法**：**不再依赖事件**。改成"小睡 20 ms + 查 padding"，pad == 0 就写一个周期。
CPU 开销可以忽略（50 次/秒），但彻底消除了这类死锁。

### 1.6 构建脚本判据错误 + BOM 丢失（最坑的一次）

- Select-String "error:" 抓不到 clang 的 "1 error generated." ⟹ **编译失败被当成成功**，
  于是拿着旧二进制测了半个多小时，还"复现"了并不存在的 bug。
- edit 工具重写 .ps1 会丢掉 UTF-8 BOM ⟹ PowerShell 5.1 按 GBK 解析中文，
  报一堆"缺少字符串结束符"。

**现在的规矩**：
1. 构建判据同时匹配 error: / error generated / ninja: build stopped / permission denied；
2. 改完 .ps1 一定要补 BOM。

## 2. 流式渲染的结构

    [生产者线程]                         [消费者线程 = 播放本线程]
     分块 4096 帧                         攒够一个周期（9600 帧）
     -> Pipeline::process（跨块保持状态）  -> write_one_period()
     -> 队列（上限 8 块）                  -> ps.played += 写入帧数

- 跳转：消费者把目标帧写入 seekFrame，epoch+1，清空待写缓冲；
  生产者看到后 Pipeline::seek_reset()（**不重建管线** —— 重建要重新设计 26 万抽头滤波器，
  秒级卡顿），并从 "目标 - 0.5 秒" 开始解码，丢掉这 0.5 秒的预热输出，避免淡入。
- 暂停：IAudioClient::Stop()/Start()（合法路径），不是"跳过事件不写"。
- 尾音：done 且不足一个周期时补静音凑满，保证最后一块不被丢掉。

## 3. 音质相关的新增

### 3.1 过采样峰值检测（ISP）

数字满幅在采样点上，DAC 重建出的模拟波形可能超幅；升频插值出的中间值同理。
用 8 抽头窗 sinc、每两个采样间插 4 个点，扫全曲取峰值：

- 已知答案验证：fs/4 正弦、相位 45 度，采样点峰值 0.7071，检测器报 **1.0044**（真的在插值）
- 边界处理：越界采样用"复制端点"，否则常量信号在文件头会被误报成 0.5548
- 超幅时按峰值预衰减（上限 -3 dB），在**重采样之前**衰减，插值出的峰就不会再溢出

### 3.2 抖动自动选型

shaper=auto：输出 <=16 bit -> NS9，<=24 bit -> LNS15，更高 -> 不整形。
（依据：整形阶数越高，带内噪声越低，但需要足够的输出位深来容纳）

### 3.3 实时音量

拖动滑块即时生效，但**不破坏逐位**：绝对音量仍在 DSP 里带抖动做过一次，
设备层只应用"当前请求 - 起播时已应用"的差值；差值为 0 时 pack() 完全走原路径。

## 4. 未解决 / 待验证（如实记录）

1. **ISP 预衰减会改变整体电平**（最多 -3 dB）。目前默认开启，用户可关。
   是否该默认关掉、只在信号链里"提示但不处理"，还需要听感验证。
2. **跳转有 <=100 ms 旧音频**（因为不 Reset）。可接受但不够干净。
3. **轮询写入**（20 ms）在极低延迟档位（buffer=20 ms）下可能不够，需要再调。
4. 歌词只支持本地 .lrc 与内嵌标签，**没有在线歌词**（版权与网络依赖，未做）。
5. UPnP 只做**发现**，不做投放：投放会经对方重采样，与"逐位"目标冲突。
6. QQ 音乐 / 网易云**截流**：技术可行（WASAPI loopback），但只能拿到系统混音后的转码流，
   与 Hi-Fi 主链路冲突，只作为降级输入源预留，未接入。详见 音乐平台截流可行性.md。
