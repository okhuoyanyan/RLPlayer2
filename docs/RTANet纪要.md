## 1. 为什么自研而不是硬啃 NAA

调研结论（见 [NAA-调研报告.md](research/NAA-调研报告.md)）：

- NAA **无公开规范、无源码、无 Wireshark dissector**；官方手册 65 页对端口/组播**提及 0 次**
- 更关键：**NAA 本身不决定音质**。决定音质的是端点的时钟、供电与缓冲策略，协议只是搬运工
- 自研反而能做更好：显式时间戳 + 抖动缓冲 + 序号，且**可以逐位验证**

（NAA 兼容仍可作为后续「互操作性」目标单独做，见打通的端口与发现机制线索。）

## 2. 协议设计

```
UDP 数据面，固定 40 字节包头（小端）：
  magic 'RTAN' | version | flags | seq | timestamp(绝对样本号)
  rate | channels | bits | frames | payloadBytes | streamId

载荷：紧凑打包 PCM（16 / 24 / 32 bit），128 帧/包 ⟹ 最大 1064 字节 < MTU
```

**关键设计**：包头带**绝对样本号**时间戳。接收端据此对齐，而不是依赖到达顺序——
这是抵抗乱序与抖动的正确做法，也是后续做**时钟漂移检测与反馈**的基础。

## 3. 实测结果（9 套测试全绿）

| 验证项 | 结果 |
|---|---|
| 打包/解包 16/24/32 bit | **逐位可逆，不符 0** |
| 包头字段（seq/ts/rate/ch/frames） | 全部正确 |
| 包长 | 16bit 552 / 24bit 808 / 32bit 1064 字节（均 < MTU） |
| **UDP 回环传输** | 发出 40400 字节 / 50 包，**收到 50 包，丢失 0，内容不符 0** |
| 抖动缓冲：**完全乱序**投入 12 包 | **输出序号连续 0..11，丢失 0** |
| 抖动缓冲：缺 2 包 | 补静音 2 包，序号仍连续，丢失计数 2 |
| 抖动缓冲：重复包投 3 次 | 识别重复 2 次，接收计数 1 |

**「回环传输逐位相同」是这条链路最重要的结论**——它证明 DSP 机到端点机的搬运不引入任何数值改动。

## 4. 本轮修掉三个真 bug

### bug 1：`UdpSocket::open(0)` 根本没绑定

我把「端口 0」实现成了「跳过 bind」，结果套接字未绑定、`getsockname` 返回端口 0，
发出去的包全部石沉大海——**回环测试收到 0 包**。
正确做法：**始终 bind**，端口 0 交由系统分配临时端口。

### bug 2：抖动缓冲的起始序号取错了

原来取「**第一个到达的包**」的序号作为起点。乱序到达时这是流的**中间**，
会导致：从中间开始输出（前面几个包永远丢失）+ 很快越界产生虚假的「丢包补静音」。
正确做法：取**已收到包的最小序号**（`map_.begin()->first`，map 按 seq 有序）。

### bug 3：`pop()` 把「还没到」和「丢包了」混为一谈

原实现一旦缓冲为空就无条件补一包静音 ⟹ **流正常结束时凭空多出一包静音**。
正确设计：

```
pop()      取不到数据时返回 false —— 这【不等于】丢包，只是「还没到」
fill_gap() 由调用方依据自己的播放时钟判定超期后调用，才补静音
```

这三条都不是笔误，而是**协议状态机的语义没想清楚**。
