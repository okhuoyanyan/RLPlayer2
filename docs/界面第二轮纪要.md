## 1. 三套主题

| 主题 | 定位 |
|---|---|
| 深色（默认） | 原来的暗色，夜里听歌不刺眼 |
| 白色 | 白天办公环境，对比度高 |
| 浅蓝 | 介于两者之间，偏冷色的浅底 |

实现方式：**所有颜色都走 CSS 变量**，html[data-theme=...] 切换整套变量。
组件样式里不允许再出现硬编码颜色 —— 否则换主题必然漏掉某一块（这是本轮定的规矩）。

变量分三类：
- 结构：--bg / --bg2 / --bg3 / --line / --shadow
- 文本：--txt / --txt2 / --mut / --mut2
- 语义：--acc / --acc2 / --acc-weak / --acc-text / --ok / --warn / --danger

切换入口有两个：顶栏右侧三个小圆点、设置页的「主题」下拉。
选择存在 localStorage（启动瞬间就能应用，不会闪一下）并同步到服务端的 rta-settings.conf。

验证：tools/uicheck.js 会依次点三个圆点，断言 document.documentElement.dataset.theme 与选中状态一致。

## 2. 信号链的"音量不更新" bug（用户报的，属实）

**现象**：拖动音量滑块，信号链里的音量仍然显示起播时的值。

**根因**：信号链的数据是**起播那一刻的快照**（ps.signal），而音量是之后由
/api/volume 实时改的（设备层做的微调）。快照当然不会变 —— 界面在展示过期数据，
用户会觉得"这软件在骗我"。

**修法**：
1. /api/status 增加两个字段：volDb（当前请求）与 startDb（起播时已应用）
2. 信号链的音量节点带上 id，tick() 每 400 ms 用实时值改写它
3. 文案区分三种状态：
   - 0.0 dB（逐位无损）
   - -20.5 dB
   - -20.5 dB（起播 -70.0 dB，实时微调 49.5 dB） ← 让用户看懂"为什么和起播不一样"

**验证**（tools/uiprobe.js，真实浏览器）：
起播 -70 dB 时打开信号链看到 -70.0 dB；改成 -20.5 后 900 ms 内变成
"-20.5 dB（起播 -70.0 dB，实时微调 49.5 dB）"；回到 0 变成 "0.0 dB（逐位无损）"。

## 3. 完整设置页

左侧导航「设置」现在打开的是**主区整页表单**（右侧面板保留最常用的几项做快捷入口）。

八组：

| 组 | 内容 |
|---|---|
| 外观 | 主题 |
| 音频输出 | **输出设备下拉**（枚举所有活动端点）、输出模式（PCM / DSD64/128/256）、采样率、位深（16/24/32）、缓冲、音量渐变 |
| 升频与滤波 | 滤波器 1x、滤波器 Nx、相位（跟随预设/线性/最小）、抽头数、阻带衰减、过渡带、两段式 |
| 抖动与保护 | 抖动/噪声整形（含 auto）、ISP 峰值保护 |
| DSD 调制器 | 阶数（5/7）、噪声整形拐点、调制器抖动 |
| EQ 与房间校正 | **EQ 文本路径（REW / AutoEq）**、IR 路径（WAV）、卷积走 GPU |
| 播放 | 循环模式、随机播放、等响度 |
| 音乐库与网络 | 添加/移除目录、重新扫描、发现 DLNA |

共 26 个控件。所有值都会落到 rta-settings.conf，重启后还在；点「保存设置」后
下一次播放生效（采样率/滤波器这类参数本来就必须重新开流）。

新增的后端能力：
- /api/devices：枚举活动音频端点（之前写死"默认设备"）
- /api/rates?device=...：按所选设备给可用采样率
- 播放参数新增：device / bits / taps / atten / transition / phase / modcut / moddith / ir / irgpu / ramp / eq
- **EQ 文本**在输入采样率上构建双二阶链（EQ 位于重采样之前），支持 REW 的
  "Filter 1: ON PK Fc 1000 Hz Gain -3.0 dB Q 1.41" 与 AutoEq 的 Preamp/Low Shelf 段落
