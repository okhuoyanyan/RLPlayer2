## 0. 愿景与定位

1. 播放器接入大模型 API(锁定 **DeepSeek `deepseek-flash`**,不用 pro 档);
2. 播放/扫描时按文件名或既有标签**自动补全全部标签**(基础元数据/封面/歌词/年份/流派/专辑艺术家);
3. 仿 Roon 的**深度资料层**:古典发行版本、乐团/指挥、创作背景、乐评、歌手生平、版本推荐——
   Roon 的元数据是其云端护城河(TiVo/Rovi 授权 + 云端识别),我们**不接 Roon**(其本地库为空的
   LevelDB 私有格式,EULA 禁逆向,Rovi 条款禁第三方永久存储),改用「多源 API + LLM 融合」重建;
4. **智能归类**:不依赖标签的多维分组(作曲家/乐团/指挥/厂牌/系列/风格/年代/来源类型),
   支持自然语言 Focus(「卡拉扬的贝多芬」「深夜弦乐」)。

配套铁律:所有源仅取**元数据**;不解密(`.mflac` 跳过)、不取音频流、限频、本地缓存、
如实 UA、产品内置合法公开源、UI **永不出现外部页面**(无 iframe/外链跳转,引用只做复制链接)。

## 1. 调研结论(浓缩,完整链接见 §6)

### 1.1 Roon(放弃,理由三重)

- 本机 Roon 全新安装(2026-10-21 20:17),数据库 570KB **空库**,无数据可爬;
- 数据库为 LevelDB/RocksDB 家族(`Database/Core/<hash>/broker_4.db/` 含 CURRENT/MANIFEST/LOCK/.log,
  本机目录结构实测确认),值是私有序列化,社区无解析先例;
- EULA 禁止逆向;官方扩展 API(9330 端口,WebSocket)合法但 item 只有 title/subtitle/image_key,
  拿不到 credits 等结构化字段;9332 私有协议虽有人逆向成功(roon-api-reverse-engineering),
  但随时会被版本更新破坏,Roon CTO「不反对」≠EULA 允许。**结论:不接 Roon,自建。**
- Roon 的元数据来源 = TiVo/Rovi(AllMusic 同源)+ MusicBrainz + 整库导入的 Tidal/Qobuz 目录,
  识别靠其云端。我们能复刻的:MusicBrainz(credits,Roon 同款来源)+ 自建识别(LLM);
  AllMusic 无公开 API,传记用 Wikipedia 替代。

### 1.2 国内平台元数据(本日实测可用,见 §2)

QQ 音乐 `musicu.fcg`、网易云音乐明文 `/api/` 均无官方个人 API,但匿名只读接口实测可用,
且有多个存活多年的第三方实现(music-tag-web 6.2k star、MusicTag 系)。法律分层:纯目录性
元数据 + 本地缓存 + 低频 + 不分发 = 低风险;音频流/解密 = 红线不做。网易开放平台需企业资质,不可用。

### 1.4 DeepSeek Search/Fetch API(2026-10-17 公开)

- 独立 HTTP API(非 chat 内 tool),Bearer 认证,与 `https://api.deepseek.com` 同域;
- `POST /v1/tools/search`:参数 query(≤128 字符,支持 site:/lang:/after: 语法)、count(≤50)、
  need_content;返回 results[](title/url/snippet/summary/rerank_score 0-3/authority 0-4/date);
- `POST /v1/tools/fetch`:参数 url;返回 title + Markdown 正文;
- `POST /chat/completions`:OpenAI 兼容,`model:"deepseek-flash"`;
- 计费 $0.75/千次成功请求(失败/空结果免费);2026-11-01 起按次计费;5 QPS 账号级限速。

**坑位记录**:Git Bash curl 的 JSON body 中的中文会被污染成非法 UTF-8(DeepSeek 报
invalid unicode code point),导致第一轮 QQ/网易/DeepSeek 假失败;改用 `\uXXXX` 转义体或
显式百分号编码后全部正常。C++ 侧字符串原生 UTF-8,无此问题。**教训:shell smoke 的中文
载荷必须 ASCII 安全;判据要看返回内容的相关性,不能只看 HTTP 200。**

#### D. 运行机制速记

播放→PLAY 挂点→meta_on_play(去重线程)→enrich_track→采纳门槛不过则零写入(无记录,可重试);

## 3. 架构(P0 落地范围)

```
播放事件 / 批量 / CLI(tools/rtatag.cpp)
   ▼
① parse(src/meta/parse.h)  标签优先 → 文件名规则拆分 → LLM 兜底(deepseek-flash,结构化输出)
② providers(后续阶段)      qq / netease / itunes / lrclib / (musicbrainz…)
③ match                    标题/艺术家相似度 + 时长差强信号(±3s)+ 专辑上下文
④ fuse                     字段级融合,优先级可配,歧义时 LLM 裁决
⑤ store(src/meta/store.h)  MetaBase:rlplayer-meta/ 文件树,每字段带 {value,source,ts,confidence}
⑥ 呈现                     /api/meta 等扩展字段;正在播放页/专辑页/艺术家页(延续现有设计令牌)
```

- `src/meta/llm.h`:DeepSeek 客户端(chat/search/fetch),model 固定 deepseek-flash,
  key 只存本地配置(rlplayer-llm.conf 或设置项),**绝不进源码**;
- MetaBase 布局:`rlplayer-meta/{entities/*,tracks/<hash>.json,covers/,facets.json,vocab/}`,
  原子写(仿 library.h 的 tmp+rename),每字段溯源,合并优先级 **user 手改 > 事实源 > AI 推断**;
- 写回文件标签(P2)走 ffmpeg remux,**PCM 逐位不变**为硬门禁;
- 网络纪律:每源令牌桶限频、失败熔断、永久缓存去重;HTTP 代理配置(本机对部分国际源直连不稳)。

### 实体模型(P3+ 落地,先行定案)

Person(角色化)/ Group(乐团·社团·组合)/ **Label(厂牌,一等实体)** / Series(企划:游戏·动画·同人原作)/
Work(交响曲 ≡ 流行歌 ≡ 同人 arrange 曲)/ Recording(演绎版本)/ Release(挂厂牌·年份·版次)/ Track(文件)。
古典四层:Composer→Work→Recording(乐团×指挥×独奏)→Release;流行退化为 Artist→Release→Track;
同人挂社团与 Series(本库样本:塞壬唱片-MSR = Label×Series;澤田なつ = 同人)。
Facet 七轴:人物(角色)/厂牌/系列/来源类型(商业·同人·OST·独立)/时间三轴(创作·录音·发行)/风格/情境。

### 内容分级(资料层,防幻觉)

L1 结构化事实(标签+MB+iTunes+QQ/网易)→ L2 权威文本(Wikipedia API 直取)→
L3 检索综合(DeepSeek search→过滤(rerank≥1.5,authority≥2,域名白名单)→fetch→**flash 只依据材料综合**,带引用)→
L4 版本推荐(MB work→recordings 结构化枚举 + AI 点评分开渲染)。
**LLM 不产生可查证事实;生成内容 UI 常显「AI 生成」标注;引用渲染为复制链接芯片,不打开浏览器。**

### UI 设计契约(延续第十二轮无边框美学)

只用现有 CSS 变量与组件词汇(.card/.trow/.badge/.ahead/.fld/.np…),三主题全过,不引入新视觉语言;
新浏览视图(作曲家/厂牌/系列)进左侧 .nav;facet 过滤器做成 .badge 芯片组;
封面/头像本地缓存后经 /api/cover 出;资料缺失=内置空态卡(--phbg+重试),**永远不用外部页面填补**;
uicheck.js 为每个新页面加断言(含「无外链」)。
