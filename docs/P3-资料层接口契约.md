# P3 资料层接口契约（里程碑②③④ 共用，2026-10-23 定）

> 用途：把「实体 → 材料 → 综合 → 富页」的**数据形状**先钉死，让 ②直连层 / ③检索层 / ④富页
> 可以并行开发而不互相改坏。任何一方要改字段，先改本文件并在 commit 里说明。
> 铁律：**LLM 不产生可查证事实**；每条可查证内容必须带来源 URL 与取回时间；
> UI 里引用一律是**复制链接芯片**（不许打开外部浏览器）；缺资料=内置空态卡，绝不用外部页面填补。

---

## 0. 内容分级（docs/元数据补全调研与规划.md §3 的落地口径）

| 级别 | 来源 | authority | 允许在 UI 里怎么出现 |
|---|---|---|---|
| L1 结构化事实 | 标签 / MusicBrainz / iTunes / QQ / 网易 / Discogs | 4 | 直接展示（如专辑年份、厂牌） |
| L2 权威文本 | 维基百科（zh/en）、萌娘百科 | 4 / 3 | 展示原文摘要，**必须带来源 URL 芯片** |
| L3 检索综合 | DeepSeek search/fetch + flash 综合 | 1 | 必须常显「AI 生成」标注 + 引用芯片；不得冒充事实 |
| L4 版本推荐 | Discogs 版本枚举（MB 当前不可达，作后备） | 4 | 结构化列表 + 每条 url；AI 点评单独分区、单独标注 |

## 1. KnowledgeMaterial（② 产出，③④ 消费）

```json
{
  "source": "wikipedia-zh",          // wikipedia-zh | wikipedia-en | moegirl | discogs | lastfm
  "kind": "biography",               // biography | genre | similar | disambiguation | credits | release_version
  "subject": "ZARD",                 // 查询用的实体名（原样）
  "title": "ZARD",                   // 页面/条目标题
  "text": "……",                      // 纯文本正文（保留段落换行）
  "url": "https://zh.wikipedia.org/wiki/ZARD",   // **必填**，无 url 的材料不许产出
  "lang": "zh",
  "fetched_at": 1792690000,          // unix 秒，**必填**
  "expires_at": 1795282000,          // 0 = 不过期；默认 30 天
  "authority": 4                     // 0..4
}
```

实体 id 一律用 `src/meta/entities.h` 的 `entity_id(kind, name)`（如 `person:<norm>`），不要另造 id。

## 2. 直连层 API（②，C++ 头文件 + CLI 取证）

```cpp
// src/meta/knowledge.h（header-only，禁止 include windows.h）
struct KnowledgeResult {
    std::string entityId;                       // entities.h 的 id
    std::vector<KnowledgeMaterial> materials;
    std::vector<std::pair<std::string,std::string>> errors;  // source → error 文本（缺 key/网络/消歧义）
    bool from_cache = false;
    bool offline = false;
};

KnowledgeResult knowledge_fetch(EntityKind kind, const std::string& name,
                                const KnowledgeOptions& opt);   // opt: lang / refresh / metabase
```

CLI：`rtatag knowledge --kind person --name "ZARD" [--refresh] [--json] [--metabase <dir>]`
（② 的验收取证入口；JSON 输出形状 = 上面的结构）。

## 3. 检索层 API（③，`/api/entity/summary`）

```json
{
  "ok": true,
  "ai": true,
  "model": "deepseek-flash",
  "generated_at": 1792690000,
  "disclaimer": "AI 生成，仅依据下方来源材料综合；可能不完整，请以来源为准",
  "sections": [
    {"heading": "创作背景",
     "paragraphs": [
       {"text": "……", "citations": ["c1","c2"]}
     ]}
  ],
  "citations": [
    {"id":"c1","title":"……","url":"https://…","source":"wikipedia-zh","fetched_at":1792690000}
  ],
  "materials_used": ["https://…","https://…"]
}
```

硬规则（③ 必须实现并单测）：
1. **每个 paragraph 的 citations 至少 1 条**；没有引用支撑的段落**不许输出**（宁可少写）。
2. citations 的 url 只能来自：a) L2 材料（② 产出）；b) L3 检索结果里通过过滤的条目
   （`rerank_score >= 1.5` 且 `authority >= 2` 且域名在白名单内）。白名单初版：
   `wikipedia.org`、`moegirl.org.cn`、`musicbrainz.org`、`discogs.com`、`allmusic.com`、
   `last.fm`、`pitchfork.com`、`gramophone.co.uk`、`bach-cantatas.com`。
3. flash 的 prompt 只允许「依据给定材料」综合；**输出必须是 JSON**（sections/citations 两段），
   解析失败就返回 `{"ok":false,"error":"..."}`，不许把裸文本塞进页面。
4. 缓存：`entities/<id>/summary-<lang>.json`，TTL 7 天；离线时返回缓存并带 `offline:true`；
   设置项 `metasummary` 默认关（用户未开时不调用 DeepSeek，页面显示空态卡 + 提示）。

## 4. 版本推荐（④ L4，`/api/entity/versions`）

```json
{
  "ok": true,
  "work": {"id": "...", "title": "Boléro", "composer": "Maurice Ravel"},
  "performances": [
    {"id":"discogs-release:915325","title":"Boléro","performers":"…","conductor":"…","orchestra":"…",
     "year":1985,"label":"TELDEC","format":"Vinyl 12\"","country":"Germany",
     "url":"https://www.discogs.com/release/915325","source":"discogs","fetched_at":1792690000}
  ],
  "complete": true,          // performances.length >= 5 且每条都有 url
  "ai_review": {"text":"…","citations":["c1"],"disclaimer":"AI 生成（可选，开关控制）"},
  "errors": []
}
```

- **Discogs 免 token 的 `/database/search` 已实测可行**（2026-10-23：HTTP 200，返回真实结果；
  匿名限频约 25 req/min，必须令牌桶）。MusicBrainz 本机当前不可达（直连与 7897 代理均超时），
  所以 L4 以 Discogs 为主、MB 作后备（可达时补 recordings）。
- `performances` 每条必须有 url；不足 5 条时 `complete=false` 并如实展示现有条目（不编造）。

## 5. UI 契约（④）

- 只用现有 CSS 变量/组件词汇（.card/.trow/.badge/.ahead/.fld/.np…），三套主题（深/浅/浅蓝）全过；
  新浏览视图进左侧 .nav（作曲家/厂牌/系列）；不引入新视觉语言。
- 艺术家页分区：**简介（L2 原文+来源芯片）→ 风格/相似（L2）→ AI 综合（仅设置开启时，常显「AI 生成」）
  → 版本推荐（古典作品页）**；每个来源渲染成「复制链接」芯片（点击复制 url 到剪贴板，**不打开浏览器**）。
- 缺资料 → 内置空态卡（--phbg + 重试按钮）；断网 → 顶部/区块横幅「离线：显示缓存（YYYY-MM-DD 取回）」。
- uicheck.js 为每个新页面加断言，必须包含：**页面内 `a[href^="http"]` 数量为 0（无外链）**、
  引用芯片存在、空态卡存在、AI 标注存在（开启时）。
- `/api/entity/knowledge`、`/api/entity/summary`、`/api/entity/versions` 均为 **GET 只读**；
  任何写操作都不在本阶段。

---

## 6. 验收（P3 整体，用户口径）

1. **5 位艺术家资料页**全带**可复制来源**（url 非空、fetched_at 非空、离线可看缓存）。
2. **3 部古典作品**版本页各 **≥5 个可溯源演绎**（每条有 url；performers/conductor/orchestra 能填就填）。
3. **幻觉抽检零硬伤**：随机抽 10 条 AI 段落，逐条核对「引用材料里是否真有该事实」；不成立即判失败。
4. **断网显示缓存**：断网后打开已抓过的资料页，仍显示内容 + 离线标注，不白屏、不报错。
