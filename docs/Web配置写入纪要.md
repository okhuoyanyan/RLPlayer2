# Web 配置写入纪要（Round 31）

代码：[tools/rtaplay.cpp](tools/rtaplay.cpp)

## 1. 补上的是什么

Round 28 记录 Web 控制面是「只读」。本轮补上写入路径，并顺带发现一个真缺陷。

```
GET  /api/config          回读配置（JSON，含转义后的文件内容）
POST /api/config          表单体 key=value&key=value，只更新给出的键
```

## 2. 实测

| 请求 | 响应 |
|---|---|
| `POST rate=96000&shaper=NS9&volume=-6`（文件不存在） | `{ok:true, updated:0, added:3}` |
| `POST shaper=NS5`（键已存在） | `{ok:true, updated:1, added:0}` |
| `GET /api/config` | 回读内容与磁盘一致 |

第二行是「只更新、不重复追加」的直接证据。

响应里内嵌了诚实的设计说明：
```json
"note":"下次启动生效（管线为整块处理，无法热改）"
```

## 3. 本轮发现并修掉的真缺陷

**`--config` 指向不存在的文件时，播放直接报错退出。**

这个行为有两处害处：
1. 用户第一次用配置（文件还没建）会直接失败，体验很差
2. **它让「用 Web API 创建配置」这条路径根本走不通** —— 因为进程起不来

已改为：文件不存在时打印提示并按默认值继续运行。

> 又是一个「失败信号指向别处」的例子：表面看是 Web API 连不上，
> 真因是配置文件加载逻辑过于严格。

## 4. Web 控制面现状

| 能力 | 状态 |
|---|---|
| 状态查询 `GET /api/status` | 可用（启动时快照） |
| 配置读 `GET /api/config` | 可用 |
| 配置写 `POST /api/config` | 可用（下次启动生效） |
| 实时播放进度 | 不可用 —— 需先把管线改成流式分块 |
| 请求加固（体积限制/并发） | 未做 —— 对外开放前必须补，目前仅监听 127.0.0.1 |
