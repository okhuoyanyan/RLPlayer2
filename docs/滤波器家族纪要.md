# 滤波器家族实现纪要（Round 4）

代码：[src/dsp/filter_families.h](src/dsp/filter_families.h)　测试：[tests/test_filters.cpp](tests/test_filters.cpp)

## 1. 实现的三条正交维度（对齐手册 4.6）

| 维度 | 选项 | 决定什么 |
|---|---|---|
| **窗函数** | Kaiser / Gaussian / Blackman-Harris / Hann | "家族性格"：poly-sinc 系用 Kaiser，gauss 系用 Gaussian，closed-form/sinc 系用 Blackman-Harris（旁瓣最低） |
| **相位** | 线性 / **最小相位** | "时间行为"——即 -lp / -mp 后缀 |
| **抽头数** | 4k / 16k / 32k / 65k / 262k / 524k | "陡峭度"：short / medium / long / xl / sinc-M |

**最小相位用倒谱法（homomorphic）严格分解**：
线性相位原型 → 实倒谱 → 折叠（因果部分加倍、反因果置零）→ 指数还原 → IFFT → 取因果前半。
不是"把脉冲右移"之类的近似。

**核心验证结论**：
1. **线性相位完美对称**：前/后能量比恒为 **1.0000**，峰值位置恒为 **0.5000**（精确到小数点后 4 位）
2. **最小相位确实消除前振铃**：峰值位置 0.5000 → **0.0003**，能量重心 16383 → **40.3**（前移约 400 倍）
3. **最小相位与线性相位幅频一致性**（倒谱分解正确性判据，−120 dB 以上区间）：
   - 32767 抽头：**0.0054 dB**
   - gauss 32767 抽头：0.0354 dB
   - 4095 抽头：0.1373 dB

## 3. ⚠️ 踩到的三个坑（都是"指标本身定义错了"，比代码 bug 更隐蔽）

**坑 1：把截止频率设在接近 Nyquist**
最初的预设用 `cutoff = 1 − transition ≈ 0.96`，结果滤波器退化成一个近似冲激——中心抽头占 96% 能量，前振铃/群延迟等时间域指标全部失去意义（测出毫无规律的 0.005~0.06）。
改为**半带型截止（0.44~0.495）**后才得到正常结果。

**坑 2：用"峰值前能量 / 总能量"判定对称性**
对称滤波器的该比值天然只有 **~0.25**，因为**峰值样本自身就占了近半能量**，且它不参与"峰值之前"的统计。我一开始断言它应 ≈0.5，全部报错。
正确判据是**前/后能量比**——线性相位应恰好为 1.0。

**坑 3：倒谱法用了绝对的对数幅度地板**
高斯窗没有旁瓣结构，阻带可深到 −300 dB 以下。用绝对值地板（1e-30）会把整段深阻带"压平"，往倒谱里塞进大量假的 −69 项，**污染整个最小相位解**（poly-sinc-lp/mp 偏差从 0.005 dB 恶化到 22 dB）。
改成**相对峰值的地板**（峰值 × 1e−15）后恢复正常。

> 共性教训：这三条没有一条是"代码写错"，全部是**判据本身定义错了**。测试通过不代表测对了东西。

## 4. 已知限制

- **最小相位幅频偏差随抽头数减少而增大**（截断效应，最小相位响应本质无限长）：
  32k 抽头 0.005 dB → 4k 抽头 0.137 dB。若要更严格，应给 -mp 预设分配比对应 -lp 更多的抽头。
- **预设表是"命名对齐"而非"参数对齐"**：HQPlayer 各家族的确切抽头数/窗参数未公开，本表按手册描述的数量级（short/medium/long/xl/sinc-M）与性格（gauss 系更平缓、closed-form 旁瓣更低）设定，属于**等效复刻**，不追求 bit 级一致。
- 尚未实现手册中的 `*-2s` 两级级联、`hb`（half-band）族、`xtr`（极端滚降）、`minringFIR`。

## 5. 2026-10-25 补充：抽头预算的计量单位

上面第 4 节的"已知限制"已部分过时（`-2s` 与 `hb` 族后来都实现了）。
**新的、更重要的一条限制**：预设表的 `taps` 是**内插域**长度，每相位抽头 `T = taps / L`，
于是同一预设在 44.1k→384k（L=1280）只剩 4~25 个抽头，通带 20 kHz 塌陷 3~5 dB、镜像只有 −30 dB。
实测与修法见 [PCM回放质量-实测与改进.md](PCM回放质量-实测与改进.md)（新增 `tapsPerInput` 制式与
`poly-sinc-tight-lp` / `apod-20k-tight` 两个可选预设）。
