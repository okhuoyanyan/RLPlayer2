# DSD 输出路径：DoP v1.1 打包纪要（Round 47）

代码：src/dsp/dop.h　测试：tests/test_dop.cpp

## 1. 为什么先做 DoP 而不是 ASIO 原生 DSD

DoP 可以**复用已经验证过的 WASAPI 独占路径**（24-bit 容器 + 交替标记），
不需要 ASIO SDK（其授权非自由许可，且要单独签约）。成本低得多。

## 2. 原理

每 16 个 DSD 位装进一个 24-bit PCM 样本：高 8 位放标记，低 16 位放 DSD 位；
标记在 0x05 / 0xFA 之间**逐样本交替** —— 接收端靠它识别出这是 DoP 而非普通 PCM。

| DSD | DSD 采样率 | 承载 PCM 速率 |
|---|---|---|
| DSD64 | 2.8224 MHz | 176400 Hz |
| DSD128 | 5.6448 MHz | 352800 Hz |
| DSD256 | 11.2896 MHz | 705600 Hz |
| DSD512 | 22.5792 MHz | 1411200 Hz |

## 3. 实测（全部通过）

| 验证项 | 结果 |
|---|---|
| 速率换算 DSD64/128/256 | 正确 |
| 打包->解包 逐位往返 | **1/2/6 声道，不符 0** |
| 标记序列 | 逐样本交替 0x05 / 0xFA |
| 非法标记 | 被正确拒绝 |
| 位图案 | 全 +1 -> 0x05FFFF；全 -1 -> 0x050000 |

## 4. 现状与下一步

**已完成**：DoP 打包/解包的完整实现与验证（纯 DSP 层，可离线测试）。

**尚未接线**（下一步）：
1. 把 SDM 调制器的 1-bit 输出接到 DoP 打包器
2. 把打包结果送到 WASAPI 独占输出（承载率由 DSD 倍数决定）
3. 在 rtaplay 暴露选项，如 --dsd 64|128|256
4. 离线写出路径：--dsd 64 --out x.wav（可用 DoP 解包回读验证）

**重要前提**：DAC 必须支持 DoP（且承载率要在它支持的范围内）。
本机已知 TASCAM X8 最高 96 kHz，**无法承载 DoP**（DoP64 就要 176.4 kHz），
因此这条路径的实际测试需要你的接收 DAC 支持 176.4 kHz 以上。
