# 音乐平台截流可行性（QQ音乐 / 网易云音乐 · Windows）

日期：2026-10-20　类型：技术调研（**未做任何实际抓取**，未下载任何破解/DRM 绕过工具）
范围：只回答「能不能截、截到的是什么、代价多大、法律上什么位置」

---

## 0. 结论先行

| 问题 | 结论 | 一句话理由 |
|---|---|---|
| 两个客户端是否产生**共享模式**渲染流？ | **是**（默认设置下） | 二者都是普通的 WASAPI/DirectSound 渲染客户端，走 Windows 音频引擎，不是自建内核态驱动 |
| WASAPI loopback 能否抓到？ | **能** | 官方文档明确 loopback 抓的就是「音频引擎输出的系统混音」 |
| 抓到的是不是原始数据？ | **不是，永远不是** | 抓点在混音之后：重采样、会话音量、音效、32-bit float 转换都已发生 |
| 切「独占/ASIO」后还能抓吗？ | **不能** | 独占流根本不经过音频引擎，且 loopback 只有共享模式一条路 |
| 有没有成熟的第三方内录工具？ | **有，且很成熟** | Audacity（GPL-2.0）、OBS（GPL-2.0）、win-capture-audio（GPL-2.0）、VB-CABLE/VoiceMeeter |
| 有没有非官方 API 直接拿音频流地址？ | **历史上有，现在生态被压制** | NeteaseCloudMusicApi 已清库归档；unlock-music 被腾讯 DMCA 下架 497 个仓库 |
| 可行性等级 | **技术上「可行」，音质上「勉强可行」，合规上「仅限个人听」** | 能录，但拿不到 bit-perfect，且不能分发 |

**直白版**：想在自己的 DSP 链里听 QQ音乐/网易云 → **可行**，代价是「系统混音后的流」。
想拿到这两个平台的**原始音频文件** → **不可行**（技术上要解密，法律上明确违法）。

> ⚠️ 与本项目既定原则冲突：`docs/音质极限分析.md` 第 5 节定的是「**只取原始文件，绝不接受转码流**」。
> loopback 本质就是「系统混音后的转码流」，所以它只能作为**降级输入源**，不能进 Hi-Fi 主链路。

## 1. 这两个客户端的音频路径

### 1.1 结论表

| 项 | QQ音乐（Windows） | 网易云音乐（Windows） |
|---|---|---|
| 播放内核 | 自研播放内核（自有解码器 + 自有 DSP/EQ） | 自研播放内核（新版 beta 起为 x64） |
| 输出 API | **WASAPI（共享/独占）、ASIO** | **WASAPI**（选定设备），无 ASIO |
| 默认状态 | 共享模式（跟随系统格式） | 共享模式（**仍有 SRC**） |
| 独占后能否被 loopback 抓 | **否** | （若开独占）**否** |
| 是否有「协作式」特殊通道 | 无；就是标准 IMMDevice 渲染 | 无；同上 |

### 1.2 证据

1. **QQ音乐确实提供 WASAPI 与 ASIO 输出选项**，用户教程给的路径是「设置 → 音频设置 → 设备设置选 WASAPI 下的设备 → 再选独占模式」。
   —— [微博用户教程](https://m.weibo.cn/detail/5302123724276661)（用户帖，非官方文档）

2. **「QQ音乐有 ASIO、网易云没有」**在发烧友圈是共识性描述，且有人实测网易云的 WASAPI **仍然存在 SRC**：
   > 「没有 ASIO 选项，wasapi 不知道为啥还是有 src，我就弃用了」
   > 「没 ASIO 还是垃圾，目前只有 QQ 音乐有」
   —— [耳机大家坛：震惊，网易云终于改了他的播放器了（2023-11）](http://erji.net/archiver/?tid-2319790.html)

   注：同一帖里也有人指出，新版网易云「终于支持各种输出了」，但**输出选项 ≠ 独占**。这一条属**社区证据，未做机器级验证**（见 §8）。

3. **QQ音乐在 Win10 上「设置来设置去都跟随系统扬声器输出规格」，Win11 下才绕过 SRC** —— 说明默认路径就是共享模式（被系统混音格式吃掉采样率）。
   —— 耳机大家坛帖（标题即结论）：`升级了win11，发现qq音乐能wasapi模式绕过系统src了`（论坛帖，可能需登录）

4. **二者都不是「自有音频引擎绕过系统」**：用户能在客户端设置里**选择 WASAPI 设备名**，这本身就证明它们调用的是 Windows 端点枚举（IMMDevice），走的是标准 WASAPI 渲染路径。

### 1.3 怎么自己验证（不需要播放可听声音也能做一半）

| 判据 | 共享模式 | 独占模式 |
|---|---|---|
| 播放时「音量合成器」里是否出现该应用的独立条目 | 出现 | **消失**（设备被独占接管） |
| 其他应用是否能同时出声 | 能（混音） | 不能（被静音/被拒） |
| `IAudioSessionManager2` 能否枚举到该会话 | 能 | 不能 |
| 系统录屏/截图工具能否录到其声音 | 能 | 不能（见下） |

第 4 条有官方口径：Windows 截图工具会直接提示「**如果打开的应用使用 WASAPI 独占模式，请更改其共享模式**」
—— [Microsoft Q&A](https://learn.microsoft.com/zh-cn/answers/questions/3998464/wasapi)

## 2. WASAPI loopback 能不能抓

### 2.1 官方机制（原文级依据）

Microsoft《Loopback Recording》：

- 「In loopback mode, a client of WASAPI can capture the audio stream that is being played by a **rendering endpoint device**.」
- 「A client can enable loopback mode **only for a shared-mode stream** (AUDCLNT_SHAREMODE_SHARED). **Exclusive-mode streams cannot operate in loopback mode.**」
- 实现方式两种：硬件若在渲染端点上提供 **loopback pin**，就用该 pin 的音频；否则「**WASAPI copies the output stream from the audio engine into the loopback application's capture buffer**」——即复制**音频引擎的输出**。

  —— [Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)

这条决定了三件事：

1. 你抓到的是**引擎输出**，不是应用的源数据；
2. **独占模式一定抓不到**（引擎根本没参与）；
3. 抓的是**整个端点**，默认分不清是哪个应用（除非用进程 loopback，见 2.4）。

### 2.2 已知限制清单（逐条对应你的问题）

| # | 限制 | 机制/依据 | 对本任务的后果 |
|---|---|---|---|
| 1 | **独占模式抓不到** | 官方原文「Exclusive-mode streams cannot operate in loopback mode」；且独占时共享流连打开都失败（`AUDCLNT_E_DEVICE_IN_USE`） | QQ音乐打开「独占」、或走 ASIO，**录到的是静音/开流失败** |
| 2 | **必然经过系统混音格式** | 应用流「通常必须与设备流同采样率、同声道数」，引擎只做 PCM↔float 的有限转换 —— [Device Formats](https://learn.microsoft.com/en-us/windows/win32/coreaudio/device-formats) | 44.1k 源 + 48k 端点 = **重采样**，且是 Windows 自带 SRC 的质量 |
| 3 | **位深「被降」是误解，但容器是 32f** | 共享混音格式一般是 32-bit float（本机实测 44100 Hz / 2ch / 32f，见 `docs/P1-WASAPI-实测纪要.md`）。float32 对 16/24-bit 整数源是**无损**的 | 真正损失在 #2 的 SRC 与 #4 的处理，不在位深 |
| 4 | **音效（APO）会叠加进来** | 端点「增强/空间音效/响度均衡」在引擎内处理后才被 loopback 复制 | 用户开着「音频增强」，抓到的就不是纯信号 |
| 5 | **会话音量可能被烘进波形** | 混音在会话音量之后 | ⚠️ **未验证**：主音量是否影响采集电平，需实测（§8） |
| 6 | **无声时不产生数据** | Audacity 手册：「WASAPI host only records loopback when there is an active signal present」 | 分轨要靠静音检测，不能靠时间戳 |
| 7 | **DRM/受保护流是否被静音** | 见下 2.3 | 对这两个客户端**通常不是问题** |
| 8 | **无法分轨、无 gapless** | 拿到的是连续混音流 | 每首歌要自己切，切点必然有误差 |
| 9 | **采样率跟随端点** | 想让 44.1k 不被 SRC，必须把**端点**设成 44.1k；换曲换率要重开设备 | 全系统其它声音陪着重采样，或被强制中断 |

### 2.3 关于「DRM 保护流是否被静音」

- Windows 确有「受保护音频」路径（PlayReady/硬件保护链路），受保护内容会绕开普通混音，loopback 拿到静音。
- **但 QQ音乐/网易云不走这条**：它们用的是**自家加密容器 + 服务端鉴权**（QQ音乐侧腾讯在 DMCA 通知里写明：`qmc / mflac / mgg` 容器、RC4 加密、512-bit 随机密钥用 TEA 封装在文件尾部 —— [GitHub DMCA 记录 2022-11-04](https://github.com/github/dmca/blob/master/2022/11/2022-11-04-qqmusic.md)）。
- 解密发生在**客户端进程内部**，解出来的 PCM 照常送进 WASAPI 渲染 → 因此**loopback 抓得到**。这正是为什么「能录」和「不能破解文件」是两件事。
- 反证：有用户在 2024 年报告「我的软件采集浏览器、**网易云音乐**是正常，只是采集不到 Teams 的声音」
  —— [Microsoft Q&A](https://learn.microsoft.com/zh-cn/answers/questions/1917877/activateaudiointerfaceasync-microsoft-teams-app)。说明网易云的流对进程 loopback 也是可见的。

### 2.4 进程级 loopback（比整体 loopback 更合适）

`ActivateAudioInterfaceAsync` + `AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK`，可**按进程（含子进程）包含/排除**抓取。

- 文档：最低支持 **Windows 10 Build 20348**（[AUDIOCLIENT_ACTIVATION_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/audioclientactivationparams/ne-audioclientactivationparams-audioclient_activation_type)）
- 实践口径：**Windows 10 2004+ / Windows 11**（OBS 官方说明，见 §3）
- 价值：同时开着 QQ音乐 + 网易云 + 浏览器时，**只抓 QQ音乐那一路**，不用整体抓再分离。
- 坑：**不是万能的**。上面那个 Teams 案例里，进程 loopback 抓不到 Teams，而设备 loopback 能抓到 → 某些应用（尤其带私有音频栈/UWP 化组件）会漏。所以「进程 loopback 失败 → 回退设备 loopback」必须做。

## 3. 第三方工具：已经有人这么做，而且做得很好

| 工具 | 许可 | 做法 | 限制 |
|---|---|---|---|
| **Audacity** | GPL-2.0 | 选 `Windows WASAPI` host + `(loopback)` 输入 | 官方称这是 Windows 上**推荐**的录音方式，全数字、不经模拟；但**无声时暂停**、设备音量滑块可能联动 |
| **OBS Studio**（28+） | GPL-2.0 | `Application Audio Capture (BETA)`，**进程 loopback** | 需 Win10 2004+ / Win11；BETA |
| **win-capture-audio**（OBS 插件） | GPL-2.0 | 同样基于进程 loopback | 需 2004+；已较少维护 |
| **VB-CABLE / VoiceMeeter** | 捐赠版（donationware，闭源） | **虚拟声卡**：播放器输出到虚拟设备，再从其对端抓 | 内部多为 32f；能否双向独占取决于驱动，**bit-perfect 不可保证** |
| **Realtek「立体声混音」等** | 驱动自带 | 硬件 loopback pin | 只对板载/内置设备有效；USB DAC、HDMI 通常没有 |
| 商业「内录」软件（Total Recorder / 各类国产录音机） | 商业 | 基本同上（loopback 或虚拟声卡）+ GUI | 音质不会比 Audacity 更好，只是封装 |

一手依据：

- Audacity 手册：「You can also choose Windows WASAPI host and the (loopback) input choice … This will record computer playback even if the computer sound device lacks its own input」
  —— [Audacity Manual](https://manual.audacityteam.org/man/tutorial_recording_computer_playback_on_windows.html)
- OBS：「As of OBS Studio 28, per-application audio sources are available for users running Windows 10 (Version 2004 or later) and Windows 11」
  —— [OBS KB: Application Audio Capture](https://obsproject.com/kb/application-audio-capture-guide)
- OBS 插件：https://github.com/bozbez/win-capture-audio （GPL-2.0，4k stars）

**共同限制**：这三种做法**没有一种**能绕开 §2.2 的第 1、2、4 条 —— 独占一定抓不到，混音格式一定生效，音效一定叠加。所谓「高音质内录」要么是把端点采样率调到与曲目一致（减少但消除不了 SRC），要么是自欺。

## 4. 非官方 API / SDK：能拿到地址，但生态已被打掉

### 4.1 现状表

| 项目 | 许可 | 状态（2026-10 查证） | 能拿到什么 |
|---|---|---|---|
| **Binaryify/NeteaseCloudMusicApi** | 无（未检出 LICENSE） | **已归档 + 清空**，仅剩一句「保护版权,此仓库不再维护」（30.2k stars） | 原为网易云 Web 接口聚合，含 `/song/url` 类接口 |

| **nondanee/UnblockNeteaseMusic** | **MIT** | 存活，最后提交 2023-06（17.3k stars） | 代理替换「无版权灰歌」为其它平台音源 |
| **lyswhut/lx-music-desktop** | **Apache-2.0** | 活跃（54.6k stars） | 播放器，音源靠**外部插件**，本体不带源 |
| **maotoumao/MusicFree** | **AGPL-3.0** | 活跃（27.7k stars） | 同上，插件化 |
| **listen1/listen1_desktop** | **MIT** | 活跃 | 聚合搜索/播放（自带各家 Web 接口） |
| **ix64/unlock-music** | — | **GitHub 返回 451（因法律原因不可用）** | QQ音乐 `qmc/mflac/mgg` 容器解密 |

### 4.2 关键事件（这才是判断依据）

1. **2022-11-04，腾讯音乐对 GitHub 提 DMCA**，一次打掉 **497 个仓库**（含全部 fork），理由写得很技术：
   音乐文件用 **RC4** 加密、每首 512-bit 随机密钥、密钥用 **TEA** 封装在文件尾部，容器为 `qmc / mflac / mgg`；工具把它们转成 MP3/FLAC 即「规避技术措施」。
   —— [原文](https://github.com/github/dmca/blob/master/2022/11/2022-11-04-qqmusic.md)　→ 复现：`GET /repos/ix64/unlock-music` 返回 `451 Repository access blocked, reason: dmca`
2. **2024-01，Binaryify 清空 NeteaseCloudMusicApi 全部代码与提交历史**，只留「保护版权,此仓库不再维护」。
   —— [IT之家 2024-01-24](https://www.ithome.com/0/746/942.htm)
3. **lx-music** 的 README 里留着完整的免责/合规条款：「使用本项目的过程中可能会产生版权数据……使用者务必在 **24 小时内**清除」「仅用于对技术可行性的探索及研究」。
   —— [lx-music-desktop README](https://github.com/lyswhut/lx-music-desktop)

### 4.3 这些 API 的真实技术限制（就算不考虑法律）

- 返回的是**带时效签名的 URL**（QQ音乐 `vkey`、网易云带 `auth` token），会过期、绑 IP/UA；
- **会员/高解析档位需要登录态 Cookie**，无 VIP 只能拿到低档甚至 128 kbps；
- **版权灰歌直接返回不可播**（这正是 UnblockNeteaseMusic 存在的理由）；
- 部分曲目返回**加密容器**，即使拿到 URL 也解不出 PCM（§4.2 第 1 条）；
- 接口是**网页端私有接口**，平台一改版就全挂 —— 清库事件已经证明这条路的寿命。

**结论**：作为「播放器功能」依赖非官方 API，等于把产品寿命绑在别人的私有接口上，且随时可能收到律师函。

## 5. 三条路线对比

| 维度 | A. WASAPI loopback 实时录音 | B. 非官方 API 直取文件 | C. 解密本地缓存（ncm/qmc） |
|---|---|---|---|
| 技术可行 | ✅ 可行，代码量小 | ⚠️ 时灵时不灵，接口随时变 | ✅ 技术上可行 |
| 拿到的是 | 系统混音后的 **32f 流** | 平台给的**原始文件/流**（非会员档） | 原始文件 |
| 音质 | **必然经过 SRC/音效/音量**，无法 bit-perfect | 好，但只到账号权限的上限 | 好 |
| 是否触碰「技术措施」 | **否**（不绕任何保护，就是录音） | 灰色（用私有接口，但未解密） | **是**（明确违法，见 §6） |
| 分发风险 | 录音本身不分发 → 低 | 中 | **高（刑事/民事）** |
| 建议 | **可作为「降级输入源」** | 不建议内置于产品 | **绝对不做** |

## 6. 结论：可行性等级 + 音质代价

### 6.1 分级

| 目标 | 等级 | 理由 |
|---|---|---|
| 把 QQ音乐/网易云的**正在播放**接进自己的 DSP 链 | **可行** | 默认共享模式，loopback 抓得到；实现成本低 |
| 同上，但要求 **bit-perfect** | **不可行** | 抓点在混音之后，SRC/音效/音量已经发生；且**无法绕过**（绕过就等于要求独占，独占就抓不到） |
| 拿到平台**原始音频文件**（无损档） | **不可行**（且不该做） | 需解密 = 规避技术措施 |
| 长期产品化依赖非官方 API | **不可行** | 接口寿命与法律风险双输 |

**一句话**：`截流能成，但截到的永远是「系统混音」；想要原始流，代价是违法。`

### 6.2 音质代价（按损失从大到小）

1. **采样率转换（最大且不可避免）**：44.1k 源 / 48k 端点 → Windows 自带 SRC。想减轻只能改端点采样率，代价是全系统跟随。
2. **端点音效/APO**：空间音效、响度均衡、「音频增强」一开，信号已被改。
3. **会话音量**：播放器内的音量滑块可能已烘进波形（⚠️ 未验证主音量是否也参与，见 §8）。
4. **32f → 整数容器**：若你要落 16-bit，必须自己加抖动（本项目的 `docs/Dither-噪声整形纪要.md` 已有 NS9/LNS15 可用）。
5. **无法 gapless / 无法精确分轨**：切点误差、首尾截断。
6. **起点延迟与缓冲**：loopback 有固定延迟，做同步显示要额外对齐。

**不受影响的部分（澄清两个常见误解）**：

- **位深不会「被降」**：32f 容器对 16/24-bit 源是精确的。
- **不会有时钟漂移**：loopback 与渲染在同一引擎时钟域，不存在模拟环回那种漂移问题（这点比「声卡模拟输出再录回来」好得多）。

## 7. 法律与合规

> 以下为技术调研中的风险提示，非法律意见。

### 7.1 法条位置（原文已核对）

- **《著作权法》（2020 修正）第四十九条**：「未经权利人许可，任何组织或者个人不得**故意避开或者破坏技术措施**，不得以避开或者破坏技术措施为目的制造、进口或者向公众提供有关装置或者部件……」
  「技术措施，是指用于防止、限制未经权利人许可**浏览、欣赏**作品……的有效技术、装置或者部件。」
  —— [中国政府网全文](https://www.gov.cn/guoqing/2021-10/29/content_5647633.htm)
- **第五十条**列举的可避开情形（课堂教学、无障碍、公务、安全测试、**加密研究/反向工程**）—— **不包括「个人欣赏」**。
- **第五十三条第（六）项**：故意避开/破坏技术措施 → 民事责任 + 行政处罚（最高 25 万元或经营额 1–5 倍）+ 构成犯罪追刑责。
- **《刑法》第二百一十七条**（修正案十一后）把「故意避开或者破坏技术措施」列入侵犯著作权罪，但以**「以营利为目的」**为前提。
- **第二十四条第（一）项**：**「为个人学习、研究或者欣赏，使用他人已经发表的作品」可以不经许可、不付报酬** —— 这是个人录音自听的落点。

### 7.2 落到本任务上的判断

| 行为 | 定性 | 风险 |
|---|---|---|
| 你自己在电脑上边听边录，自己听 | 落入第 24 条(一) 的**合理使用**；**不涉及**第 49 条（没有解密、没有绕保护） | **低** |
| 录完发到网上 / 传给朋友 / 做成资源站 | 复制 + 信息网络传播 → 侵权 | **中高（民事）** |
| 批量录制建库、卖资源 | 可能触及 217 条（营利） | **高（刑事）** |
| 用 ncm/qmc 工具解密文件 | 明确规避技术措施，第 49/53 条 | **高**；已有判例：[最高检指导办理全国首例「故意避开或者破坏技术措施型」侵犯著作权案](https://www.spp.gov.cn/spp/zdgz/202402/t20240228_645144.shtml)（2023 判决，有期徒刑 3 年 2 个月至 1 年，罚金 70 万至 8 万元） |
| 在**产品里**内置解密/抓取 | 变成「提供主要用于避开技术措施的装置」（49 条 + 53 条(六)） | **极高** |

### 7.3 还有一层：用户协议（合同风险，和法律风险独立）

两个平台的用户协议通常禁止「复制、录制、转售、以技术手段获取服务内容」。违约后果是**封号/停止服务**，与著作权责任是两条独立的线。产品若引导用户这么做，还会牵出**不正当竞争**。

### 7.4 本项目的红线（建议写进 README）

1. **不做**任何 `ncm / qmc / mflac / mgg` 解密，不内联 `ncmdump`、`unlock-music` 之类实现。
2. **不内置**任何非官方 API（NeteaseCloudMusicApi / QQMusicApi / UnblockNeteaseMusic）作为音源。
3. 若做 loopback 输入：定位为**本机录音功能**（等价于「给 Audacity 装了个 DSP」），**不做**自动分轨、自动命名、批量入库、导出分享。
4. UI 上明确标注「**非 bit-perfect：已经过系统混音与重采样**」。

## 8. ⚠️ 未验证项 / 下一步（都是可执行的）

| # | 待验证 | 怎么验（不需要可听声音） |
|---|---|---|
| 1 | 本机 loopback 是否真能收到 QQ音乐/网易云的流 | 用 `-60 dBFS` 正弦在目标端点播放，同时 loopback 录 2 秒，看 RMS 是否 > `-70 dBFS`（**遵守铁律 1：不可听电平**） |
| 2 | 主音量/会话音量是否影响采集电平 | 固定源电平，扫系统主音量 0/50/100%，比较录到的 RMS |
| 3 | 网易云当前版本是否提供「独占」 | 播放时看「音量合成器」是否还有该应用条目；有=共享 |
| 4 | QQ音乐「独占」下 loopback 的表现 | 开独占后 `IAudioClient::Initialize` 是返回 `AUDCLNT_E_DEVICE_IN_USE` 还是开流成功但全是静音 —— 决定错误处理怎么写 |
| 5 | 端点设 44.1k 时 SRC 是否真的 1:1 | 44.1k 已知信号 → loopback → 与源做频域比对（延迟无关判据，参见 `docs/滤波器家族纪要.md`「三个坑」） |
| 6 | 进程 loopback 对这两个客户端的命中率 | 用 `PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE` 各抓一次，失败则回退设备 loopback |
| 7 | 长期稳定性 | 连续 30 分钟，统计丢包/断流（`IAudioCaptureClient` 的 `AUDCLNT_BUFFERFLAGS_DATA_DISCONTINUITY`） |

**如果要做成功能，建议的最小实现**：

`WASAPI loopback 采集（44.1k/32f，事件驱动） → 直通现有 DSP 链 → 标注「非 bit-perfect」`
并且**只在用户主动点击「录制系统声音」时启动**，不做后台常驻、不做自动曲库。
