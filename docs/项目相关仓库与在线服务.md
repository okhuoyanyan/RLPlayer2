## 三、Mac 分支已经实现的反馈链路（可直接借鉴/移植）

文件位置（在 Mac 仓里）：
```
worker/feedback-worker.js        Cloudflare Worker（10192 B，完整实现）
tools/mac_feedback.h             客户端接口
tools/mac_feedback.mm            客户端实现（macOS）
tests/test_mac_feedback.cpp      测试
.github/ISSUE_TEMPLATE/bug_report.yml
```

**架构**（用户 2026-10-27 确认要沿用）：
```
客户端 ──POST（无凭据）──▶ Worker ──GitHub API──▶ Issue
                              │
                              ├─ token 只在 Worker Secrets
                              └─ 诊断包 → R2（配了才传，没配就在 issue 里明说未送达）
```

**Worker 已实现的安全措施**（移植时保留）：
- 正文 16 KB 上限、诊断包 8 MB 上限（base64 解码后）
- 诊断包必须是合法 ZIP（`PK\x03\x04` 魔术字节）
- 按 IP **哈希后**软限流 5 条/分钟（用 Cache API，不需要 KV/D1）
- 只接受 `POST` + `application/json`，其它 405/415
- 只写 issue，无 eval / 无 shell / 无动态 URL
- 不收邮箱、不存真实 IP

**踩过的坑（Windows 侧同样适用）**：
- **CORS 必须带**。`http://127.0.0.1:8899` → `https://xxx.workers.dev` 是跨域；
  不回 CORS 头时页面只看到 `Failed to fetch`，但**服务端其实已经建好 issue**（用户以为没发出去）。
  必须回 `Access-Control-Allow-Origin: *` + 处理 `OPTIONS` 预检（204）。
