## 1. 卷积引擎：均匀分块 FFT（uniformly-partitioned overlap-add）

百万抽头的室内校正 IR 用直接卷积不可实时，必须分块 FFT。

```
每个 B 样本输入块：
  1) 补零到 2B 后 FFT
  2) 存入输入谱环形缓冲
  3) 累加 Σ_p H[p] · ring[head − p]
  4) IFFT 得 2B 样本；前 B 与溢出缓冲相加输出，后 B 存为溢出
```

**关键性质：零延迟。** H[0] 与「当前」输入块相乘，其贡献立刻出现在本块输出的前 B 个样本里，
尾巴进溢出缓冲——不需要额外一整块缓冲延迟。这对音量控制与实时性的意义很大。

## 2. 实测结果（6 套测试全绿，27 秒）

### 卷积：与直接线性卷积逐样本比对

| 块大小 | 段数 | 群延迟 | 相对误差 |
|---|---|---|---|
| 256 | 128 | 0 | **1.02e−14** |
| 1024 | 32 | 0 | **1.51e−14** |
| 4096 | 8 | 0 | **5.41e−14** |

IR 长 32768（指数衰减噪声，模拟室内校正），输入 40000 样本随机信号。
**零延迟验证**：输入 delta（单脉冲）→ 输出应直接等于 IR 本身，最大偏差 **2.23e−14**。

### 双二阶 EQ（手册 7.3 的 `iir` 插件全类型）

10 种设计的**解析幅频响应**与**脉冲响应实测幅频**在 20 Hz–20 kHz 对数扫描上完全一致：
**最大偏差 0.0000 dB**（peak / lshelf / hshelf / lp / hp / notch / ap / lp1 / hp1）。
另验证 peak 滤波器在 f0 处增益**精确等于设定值**（6.0000 dB 对 6.0000 dB）。

### 延迟插件（手册 7.2）

- 样本延迟：脉冲精确出现在第 137 个样本，峰值 1.0
- 距离换算：1 米 = **140 样本**（48000 Hz，v = 343.956 m/s），与理论值一致

### Matrix 路由

串扰混合（L→R/R→L 各 −6 dB）逐样本精确：L=0.374703 对预期 0.374703；
负增益实现反相（M/S 处理用）验证通过。

## 3. 本轮踩的坑：**又是测试的错，不是代码的错**

### 坑 1：越界读导致 ACCESS_VIOLATION

零延迟验证里，我只喂了 2048 个输入样本（4 块），却去比对 **32768 个** IR 样本——
`got[i]` 越界读，直接段错误（0xC0000005），而且 **printf 缓冲让前面所有输出都丢了**，
一度不知道崩在哪。

**教训**：测试程序开头加 `setvbuf(stdout, nullptr, _IONBF, 0)`，崩溃时不丢输出。

### 坑 2：拿「没被处理过的样本」去比对

输入 40000 样本不是块大小（256/1024/4096）的整数倍，尾部不足一块的样本根本没进入卷积器，
y 数组里还是 0，却参与了比对 → 报出 **72% 相对误差**的假失败。

证据：4096 块时报 83.7%（尾部剩 3136 个未处理样本，更多），256 块时报 71.8%（尾部剩 64 个）。
**误差大小与未处理尾部长度严格对应**——说明是比对区间的问题，不是卷积器的问题。
而同一时刻 delta 测试偏差只有 2.2e−14，已经证明卷积核本身是对的。

**教训**：当同一模块的两个测试给出矛盾结论时，先怀疑测量方法。

## 4. 对整体架构的意义

- 卷积引擎可直接用于手册第 6 章的「Convolution engine」（WAV IR、Expand HF）与
  第 7 章 Matrix 的 WAV 卷积插件
- 双二阶覆盖了手册 `iir` 插件的全部类型，配合 AutoEq / REW 文本解析即可做耳机/房间 EQ
- 延迟插件覆盖手册 `delay` 插件的 s / t / d 三种参数形式
- **零延迟特性**让卷积可以放在音量控制之前而不引入额外延迟
