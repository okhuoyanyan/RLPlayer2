# N300 / DC-Elite 爆音 — 真机实测结果（2026-10-24）

> 分支：`fix/underrun-p0`（基于 `v1.3.15` / `9ce2e73`）
> 设备：iBasso DC-Elite（USB DAC，已知良好对照）、EDIFIER N300（故障机）
> 方法：`tools\rtaweb.exe` 走**真实 GUI 渲染路径**（`render_loop`），
> 用 `/api/play` 驱动，读 `rlplayer-playback.log` 的 `PLAY/PLAYBUF/STAT/WFAIL/DEVICE_LOST`。
> 铁律 4：本文只写实测数字，未测项在 §5 单列。

## 1. 结论

| 缺陷 | 归属 | 状态 |
|---|---|---|
| **A. 补料太慢**（每次断流 19.6 ms，约 9 次/秒）——DC-Elite「持续啵啵啵」 | 播放器 | **已定位并实测修复**（`dryms` 10796 → 0） |
| **B. N300 从 USB 总线掉线**（PnP ID 1010） | 设备侧 | 播放器只能如实报错（`DEVICE_LOST`），不能修 |

**关键否定**：吞吐率始终是 1.000，`STARVING` 判据（阈值 0.90）永远不触发。
本缺陷只能由 `dry` / `dryms` 看见。

## 2. A/B：先写后等 + 等待上限 per/2

同设备、同曲、同参数（48 kHz / 24 bit / buffer 100 ms = 4800 帧 / per 480 帧 / vol 0 / 55 s），
只切 `RTA_FAST_FEED`：

| 指标 | 默认 | `RTA_FAST_FEED=1` |
|---|---|---|
| `dry` | **546** | **10** |
| `dryms` | **10796 ms** | **0 ms** |
| 吞吐 `Δpos/Δ墙钟` | 1.000 | 1.000 |
| `ev` | 551 | 550 |
| `evint` | 100 ms | 100 ms |

原始 STAT：

```
默认        ... w0=2242 wr=551 zp=2242 zs=0 zo=0 zr=pad=full per=480 bf=4800 dry=546 dryms=10796 ev=551 evint=100
FAST_FEED=1 ... w0=9693 wr=550 zp=19925 zs=0 zo=0 zr=pad=full per=480 bf=4800 dry=10  dryms=0     ev=550 evint=100
```

`dryms/dry` = 10796/546 = **19.77 ms**，与旧的 20 ms 轮询上限吻合：
每次都是「等到下一个轮询才发现缓冲空了」。

## 3. 根因（文件:行号，v1.3.15）

```cpp
// src/audio/render_loop.h:443（修改前）
const bool waited = sink.wait_event(20);          // 先睡，上限 20ms
...
const size_t w = sink.write_available(pend.data(), pendFrames);   // 后写
```

- 设备事件实测 `evint = 100 ms` 才来一次 ⟹ 靠事件唤醒等于每 100 ms 才补一次；
- 等待上限 20 ms ⟹ 每次补料最坏迟到 20 ms；
- `per = 480` 帧 = 10 ms，即轮询上限是 **2 × 设备周期**。

## 4. 改动

| commit | 内容 |
|---|---|
| `381dbe0` | `quantize_period_write` 不再丢弃不足一个周期的余量（DC-Elite 现场 82% 的 `w0` 是它）；`OutSink::zero_other()` + STAT `zo=` 使归因闭合 |
| `7170280` | 循环改为「先按可用空间补写 → 写不进去才等事件」，等待上限 `per/2`；由 `RTA_FAST_FEED=1` 承载，默认路径逐字不变 |

`dry` 的采样点同步改为【第一次写之前】的 `padBefore`/`pendBefore`——
否则「先写」会让 `pad==0` 不再出现，等于把判据改瞎（铁律 3）。

## 5. 未验证 / 已知问题

1. **N300 未复测**：本次三组里 N300 又一次 `surprise removed`（PnP 1010），
   且这次是 **48 kHz** —— 「96k 专属」的假设可以划掉。
2. **开关尚未转正**：默认仍走旧时序；转正前必须按新时序更新
   `tests/test_render_loop_dry.cpp` 的 mock 时钟模型（它假设「时钟只在 wait_event 时推进」）。
3. **计数瑕疵**：`zp` 按 `write_available` 调用计，而 `w0` 按轮次计；
   一轮可能调用两次 ⟹ `zp` 会大于 `w0`（现场 19925 vs 9693），M4 归因闭合失真，需修。
4. **未做 10 分钟长测**：本次单组 55 s。
5. **未做听感确认**：本次为统计量验证（用户在场且已授权放声，但仍应以长时听测为准）。
