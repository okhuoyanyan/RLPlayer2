# NAA 端点发现纪要（Round 50）

代码：tools/naa_scan.cpp

## 1. 为什么用端口扫描而不是协议发现

Round 1 的调研结论：NAA **无规范、无源码、无 Wireshark dissector**，
发现报文的逐字节格式未知。但 networkaudiod **固定监听 TCP/UDP 43210** ——
端口是否开放是可靠且无需协议知识的判据。

两种探测并行：
1. 主动扫描本网段 TCP 43210（32 线程并发，短超时）
2. 加入 Round 1 提取到的组播组（224.0.0.199 / 239.192.0.199）被动监听通告

全程只读探测，不涉及任何音频输出。

## 2. 实测（本机 192.168.50.140 / 24）

```
[1] 扫描本网段 192.168.50.1-254 的 TCP 43210 ...
    未发现开放 43210 的主机
[2] 被动监听 NAA 组播 4 秒 ...
    已加入 224.0.0.199 / 239.192.0.199
    监听期间未收到任何 NAA 报文
```

## 3. 这个结果的含义

**本网段没有 NAA 端点。** 可能原因：

- NAA 设备不在本网段
- 设备未开启 / 未运行 networkaudiod
- 防火墙拦截

## 4. 对目标第 2 项的意义

目标第 2 项是「复刻 NAA 或改用开放协议」。这道题**现在有了明确的分叉条件**：

| 情况 | 应该走的路 |
|---|---|
| 用户的接收 DAC 支持 NAA，且能连上网络 | 值得投入逆向 NAA（有对接目标可验证） |
| 用户的 DAC 只支持 USB / DLNA | NAA 逆向没有落地对象，应专注 RTANet 或 UPnP |
| 暂时无法确认 | 先用本工具扫一遍（工具已就绪） |

**在此之前继续投入 NAA 逆向是不合理的** —— 没有对接目标，无法验证，
而且调研已确认 NAA 本身不决定音质（协议只是搬运工）。

## 5. 用法

```
naa_scan                          # 扫描默认网段 192.168.50.x
naa_scan --subnet 192.168.1.      # 指定网段
naa_scan --listen 10              # 组播监听 10 秒
naa_scan --timeout 800            # 放宽单机超时（跨网段时有用）
```
