## 0. 一句话结论

**能测出来的最大余量不在"纹波/阻带/群延迟"这些数字上，而在抽头预算的计量单位上。**

原型是在**内插域**设计的，每相位抽头数 `T = totalTaps / L`（L = 输出率/输入率的最简分子）。
于是同一个 4095 抽头预设：

| 输出率 | L | T（每相位抽头） | 20 kHz 处 | 阻带最差 |
|---|---:|---:|---:|---:|
| 44.1k→88.2k | 2 | 2047 | −0.00 dB | −148 dB |
| 44.1k→705.6k | 16 | 255 | −0.00 dB | −110 dB |
| 44.1k→192k | 640 | **6** | **−5.9 dB** | **−8.3 dB** |
| 44.1k→384k | 1280 | **4** | **−5.1 dB** | **−6.6 dB** |

也就是说：**同一个预设，换个输出率，质量能差 150 dB**；而 192k/384k 恰好是 PCM 升频最常见的两个目标。

已落地改进（可选、可回退）：新增 `tapsPerInput` 制式（每输入样本的内核长度）+ 2 个预设
`poly-sinc-tight-lp` / `apod-20k-tight`，把频响与输出采样率**解耦**。既有 50 个预设的系数与输出
**逐位不变**（`tests/test_filters.cpp` 第 9 节有容差基线）。

## 1. 量测方法（先保证指标能证明要证明的事）

1. **原型直取**：所有频响/群延迟都在 `PolyphaseResampler::prototype_into()` 给出的
   *信号路径实际使用的那批系数* 上量测，不另写一份设计代码（否则测的是另一支滤波器）。
2. **THD+N 用单音最小二乘相减**，不用加窗 FFT 的泄漏底当噪声底：拟合 `a·cos + b·sin + dc`
   后减掉，残差 RMS / 基波 RMS。分析窗长取**相干长度**（1 kHz 整数个周期）。
   - ⚠️ 本轮踩的坑：一开始用非相干窗长做谐波投影，**所有预设都读出同一个 −57 dB 的 THD**
     ——纯泄漏，不是失真。改成相干长度后 poly-sinc-lp 的 THD 落在 −224…−256 dB。
3. **频率轴必须止于内插域 Nyquist**。超过 `fsInt/2` 后 DTFT 镜像回来，会把通带的 0 dB
   读成"阻带最差 0 dB"。第一次跑 L=2 的表就出现了这个假数据。
4. **满幅与 −60 dBFS 两档都测**（铁律 3）。实测两者对**线性**滤波器完全一致（残差与信号成正比）
   ——这本身是个结论：重采样器没有电平相关的非线性；电平相关的行为只在后面的量化/调制级。
5. 前/后振铃：`pre_post_ratio`（对称滤波器恒为 1.0 ⟹ 只能用来看 -mp；见"三个坑"之坑 2）。

## 3. 关键发现：抽头预算与 L 耦合（帕累托表）

Kaiser 关系：每输入样本抽头 `T ≈ (A−8)/(14.36·tr)`（A = 阻带 dB，tr = 过渡带占输入 Nyquist 比例）。

| 预设 | tr | A | T_need | L=2 时 T/T_need | L=1280 时 T/T_need |
|---|---:|---:|---:|---:|---:|
| poly-sinc-short-lp | 0.100 | 120 | 78 | **26×** 富余 | **0.05×** 不足 |
| poly-sinc-lp | 0.040 | 180 | 299 | **55×** | **0.08×** |
| poly-sinc-long-lp | 0.015 | 200 | 891 | **147×** | **0.23×** |
| sinc-M | 0.010 | 220 | 1 476 | **178×** | 0.28× |
| sinc-LL | 0.004 | 190 | 3 169 | **331×** | 0.52× |
| poly-sinc-tight-lp（新） | 0.020 | 140 | 460 | **1.11×** | **1.11×** |

⟹ 同一张表里既有**浪费 26–331 倍**抽头（低 L）的预设，也有**缺 2–20 倍**抽头（高 L）的预设。
"哪个指标还有明显余量"的答案是：**抽头预算的分配本身**，而不是纹波或阻带数值。

## 4. 改进（已落地，可选、可回退）

### 4.1 机制：`ResamplerConfig::minTapsPerInput`

```cpp
// resampler.h 构造函数内（默认 0 ⟹ 这一支永不执行 ⟹ 老路径逐位不变）
T_ = total / L_;
if (cfg.minTapsPerInput > 0) {
    T_ = cfg.minTapsPerInput;
    if (cfg.maxPrototypeTaps > 0 && (long long)T_ * L_ > cfg.maxPrototypeTaps)
        T_ = std::max<long long>(4, cfg.maxPrototypeTaps / L_);   // 内存/启动时间上限
}
total = T_ * L_;
```

配合 `FilterPreset::tapsPerInput` 与 `apply_preset()` 透传。两段式路径的
`T1` 也优先取该值（否则两段式会继承同一个 bug）。

### 4.2 两个新预设（表尾追加，既有 50 个预设一字未改）

```cpp
{ "poly-sinc-tight-lp", 32767, 0.020, 140, Kaiser, Linear, false,false,64, false, 0,0,          512 },
{ "apod-20k-tight",     32767, 0.100, 140, Kaiser, Linear, false,false,64, true, 18.4k,21.8k,  512 },
```

## 5. 诚实边界：哪些"测得出"，哪些"听得出"

### 5.1 真有可测提升（也大概率听得出来）

1. **384k/192k 下短抽头预设的高频塌陷**：−5.1…−5.9 dB @20 kHz、10 kHz 处已 −1 dB。
   这是**可听**的（年轻耳朵 20 kHz 可闻；10 kHz −1 dB 属于轻微但可辨的偏暗）。
   修法：换 `poly-sinc-tight-lp`（或接线后按预设自动）。
2. **同上的镜像/杂散**：−29 dBFS 的 1 kHz 镜像（43.1/87.2 kHz）。直接听不见，但会
   占用动态余量、在 DAC/功放/扬声器里互调。THD+N 从 −29 提升到 −177 dBFS 是 148 dB 的实测改善。
3. **apod 家族在高 L 下完全失效**：−0.1 dB 点从 18.6 kHz 掉到 2.9 kHz（等于给音源加了
   一个巨大的高频斜坡），阻带 −6.5 dB。修法：`apod-20k-tight`。

### 5.2 理论上还能提升，但听不出来

1. **通带纹波**：现状 0.0000–0.059 dB（除塌陷的那几个）。24-bit 系统的本底是 −144 dBFS，
   0.01 dB 的纹波 = −60 dB 量级的反射，完全在掩蔽阈以下。**没有余量可挖**。
2. **阻带从 −145 dB 提到 −250 dB**：24-bit 本底 −144 dB，人耳在正常音量下的动态范围更小。
   **纯数字游戏**（这条与本仓库 `docs/音质极限分析.md` 的结论一致）。
3. **群延迟平坦度**：线性相位预设恒等于 (N−1)/2（实测偏差 0.000 输入样本）——对称 FIR 的
   数学恒等式，**不可能更平坦**。`-mp` 的 0.08–15.7 输入样本（1.8–356 µs）变化是最小相位
   设计的固有代价，不是缺陷。
4. **前/后振铃能量比**：对称滤波器恒为 1.0000（= 峰值前 49.9% 能量）。想减小只能换
   `-mp`/切趾（那会改变"声音是什么"），不是"优化得更好"。
5. **T 从 512 再往上**：T=1024 只多 0.09 kHz 通带 + 8 dB 无意义阻带，代价翻倍。

## 6. 还能做什么但没做（按性价比排序）

1. **把抽头地板默认打开（需决策）**：在 `resampler.h` 里对**所有**预设加
   `T_floor = (A−8)/(14.36·tr)`。实测效果等同于 3.1 表：192k 下 `poly-sinc-lp` T 51→299、
   384k 下 25→299，20 kHz 从 −1.56/−3.31 dB → ≈0 dB，阻带 → −90…−110 dB；
   88.2k/705.6k **完全不变**（那里 T 早已富余）。代价：192k/384k 每输出样本乘加 5.9×/12×，
   系数表 0.26 MB → 3 MB；且**会改变**这些既有预设在高 L 下的输出（不再逐位回归）。
   本线按纪律**没有默认打开**，只提供 2 行接线的可选路径。
2. **两段式在 M>1 时从不启用**（`resampler.h: `if (cfg.twoStage && M_ == 1 && L_ >= 8)`）：
   44.1k→384k 的 M=147，两段式永远不触发。放开后可用"第一级整数倍 + 第二级宽过渡带"把
   T=512 的代价降到约 200 乘加/输出样本（实测同类：单级 512 → 两级 ≈201）。
   风险：会改变 11 个 `*-2s` 预设在 M>1 下的输出。
3. **`-mp`（最小相位）版的 tight 预设**：倒谱法要 8× 零填充，T=512、L=1280 时内插域原型
   655 k 点 ⟹ FFT 5.2 M 点、峰值内存 ~300 MB、启动 ~1 s。需要先把倒谱法改成单边/分段实现
   才能支撑大 `T·L`。（本条**归 DSP 本线**，但工作量 > 本轮的 1~2 个改进点。）
4. **抖动/整形对比（已测，未改）**：见下表。结论是 24-bit 下没有可听余量，但 16-bit 下
   `NS9`/`LNS15` **没有加抖动**，谐波失真比 TPDF 差 20 dB——这是 dither.h 的真实缺陷，
   修法是"整形环内也注入 TPDF"（会改变既有输出，需单独决策）。

   | 24-bit，1 kHz | THD+N | THD | 噪声底 |
   |---|---:|---:|---:|
   | none（纯舍入） | −140.0 | −152.3 | −149.0 |
   | RPDF | −137.1 | −170.4 | −146.1 |
   | **TPDF** | −135.4 | −169.6 | −144.5 |
   | NS9 | −137.5 | **−149.7** | −146.5 |
   | LNS15 | −137.5 | **−150.8** | −146.5 |

   | 16-bit，−60 dBFS | THD+N | THD |
   |---|---:|---:|
   | none | −38.0 | −49.3 |
   | RPDF | −35.0 | −67.6 |
   | TPDF | −33.3 | −67.2 |
   | NS9 | −35.7 | **−47.0** |
   | LNS15 | −35.9 | **−48.5** |

   ⟹ 16-bit 下 `NS9/LNS15` 的谐波失真比 TPDF 差 ~20 dB（因为它们不加抖动，误差反馈只整形
   不去相关）。24-bit 下全部在 −135…−150 dBFS，**听不出来**。
5. **`poly-sinc-tight` 的 UI 文案**：`/api/filters` 显示的是 `taps`（32767），对内核长度家族
   会误导（真实原型抽头 = 512×L，384k 时 655 360）。需要在 `src/net` 侧加一列（本线无权改）。
6. **1x 域（`make_filter`）的抽头语义**与重采样器不一致：新预设的 1x 分析仍用 `taps=32767`。
   目前只影响 `filter_report`/`test_filters` 的 1x 视角，不影响播放路径。

## 7. 复现

```powershell
# 独立构建目录
$env:Path='C:\Program Files\AMD\ROCm\7.2\bin;'+$env:Path
cmake -G Ninja -S . -B build-quality -DCMAKE_BUILD_TYPE=Release `
      -DCMAKE_CXX_COMPILER='C:/Program Files/AMD/ROCm/7.2/bin/clang++.exe'
cmake --build build-quality --target test_filters test_apodizing test_resampler test_monitor_dsp
cd build-quality; ctest -R 'filters|resampler|apodizing|dsp'

# 量测工具（不在 CMake 里，手工编译；未接进 ctest 以免门禁变慢）
cd ..
clang++ -std=c++20 -O2 -I src tests/pcm_quality_report.cpp -o build-quality/pcm_quality_report.exe
.\build-quality\pcm_quality_report.exe --metrics    # 频响/群延迟/振铃
.\build-quality\pcm_quality_report.exe --thdn       # 端到端 THD+N + 镜像
.\build-quality\pcm_quality_report.exe --rate       # 输出率不变性
.\build-quality\pcm_quality_report.exe --pareto     # 抽头预算帕累托 + T 扫描
.\build-quality\pcm_quality_report.exe --dither     # 抖动/整形对比
.\build-quality\pcm_quality_report.exe --cost       # CPU/内存代价
.\build-quality\pcm_quality_report.exe --hash       # 原型系数哈希（逐位回归基线）
```

> `--metrics/--thdn/--rate/--pareto` 用 `-O2`（无 fast-math）编译，数值与 Release 包
> (`-O3 -march=native -ffast-math`) 的差异在 1e-11 量级，对本文所有 dB 级结论无影响。
