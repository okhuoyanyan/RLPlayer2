# 时钟漂移检测纪要（Round 14）

代码：[src/net/drift.h](src/net/drift.h)　测试：[tests/test_drift.cpp](tests/test_drift.cpp)

## 1. 为什么必须做

DSP 机与端点机是**两个独立晶振**。哪怕只差 10 ppm，**1 小时累积 36 ms**——
端点缓冲迟早会溢出（丢样）或耗尽（断音）。这是两机方案音质的最后一环。

NAA 用回传 position 做流控；我们做得更明确：**直接估计 ppm 并给出速率补偿建议**。

## 2. 方法

对滑动窗口内的 `(本地时间 t, 流时间戳/采样率)` 做**最小二乘直线拟合**：

```
slope == 1  ⟹ 无漂移
slope >  1  ⟹ 端点消费比发送慢 ⟹ 缓冲在涨
slope <  1  ⟹ 端点消费比发送快 ⟹ 缓冲在掉
漂移(ppm) = (slope − 1) × 1e6
```

**关键**：直接用时间戳/本地时间拟合，**不依赖设备位置计数**——
后者在实测中被量化到缓冲边界（Round 1 / Round 6 反复确认过）。

## 3. 实测精度（全部通过）

| 场景 | 注入 | 估计 | 误差 |
|---|---|---|---|
| 无漂移 | 0 ppm | +0.00 ppm | **0.000** |
| 无抖动 ×7 组 | −100 … +200 ppm | 完全一致 | **0.000 ppm** |
| ±500 µs 网络抖动 | −50 ppm | −50.48 | **0.484 ppm** |
| ±500 µs 网络抖动 | 0 ppm | −0.52 | 0.519 ppm |
| ±500 µs 网络抖动 | +50 ppm | +49.48 | 0.519 ppm |

**±500 微秒随机抖动下仍能测到 0.5 ppm 以内** —— 相当于 1 小时累积误差 < 2 ms。
另外验证了：不同窗口长度都准确、**补偿方向正确**（端点消费慢 80 ppm ⟹ 建议 −80 ppm）、缓冲水位换算精确。

## 4. 后续接线

目前只是「检测器」。要形成闭环还需：

1. 端点把估计的 ppm 通过控制面回传给发送端（控制面已有 TCP 通道）
2. 发送端据此微调输出速率——两种做法：
   - **异步重采样（async SRC）**：按 ppm 微调重采样比，音质影响最小，推荐
   - 极端情况下丢/插单个样本：简单但有可闻风险，不推荐
3. 缓冲水位作为二级反馈（慢速外环）
